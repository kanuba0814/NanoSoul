# NanoSoul 项目宪法

> 本文档锁定 NanoSoul 项目的**不可动摇的核心决策**。任何讨论遇到这些主题时，以本文档为准。

---

## 1. 项目本质

NanoSoul 是参加 **2026 第九届全国大学生嵌入式芯片与系统设计竞赛・芯片应用赛道（嵌赛）/ 乐鑫赛道** 的参赛作品。同时具备产品化潜力。

- **比赛官网**：www.socchina.net
- **赛题平台**：乐鑫 ESP32-P4（**乐鑫 2026 年首次加入嵌赛，无往届乐鑫获奖样本可循**）
- **主控指定**：ESP32-P4 或 ESP32-S3 二选一；选题一/二/三推荐 P4
- **主报选题**：**选题一（嵌入式边缘AI应用，P4）**，文档说明同时覆盖选题二（人机交互）、选题三（运动控制）
- **违规红线（原文）**：作品主要功能代码必须运行在乐鑫芯片上。若仅用作通信或简单 IO 控制，主要功能由第三方芯片实现，将被视为违规选题。
- **杀手锏**：现场**断网**演示本地感知决策闭环，正面回应红线、证明 P4 是"主角"。

## 2. 一句话定位

> **NanoSoul 是一台具备主动感知能力的桌面陪伴机器人。基于 ESP32-P4 的视觉、运动和图形性能，它能在本地识别主人的存在、表情与行为，自主决策何时该陪伴、何时该退后；结合云端大模型实现深度对话，并通过工具调用接入家居生态。**

## 3. 团队模型（单人负责制）

> 由原"三人分工 + 接口契约"改为**单人负责制 + AI 协同 + 杂事外包**（详见《03_个人作战手册与技术栈》）。

| 角色 | 职责 |

| **你（全栈 Owner）** | 结构 + PCB + 底层固件 + 传感器/运动 + 显示/表情 + AI/Agent + WebUI + OTA + 整机联调，所有技术决策 |

## 4. 核心架构原则

### 4.1 P4 必须是"主角"，不是"前端机"
- 所有决策性逻辑必须在 ESP32-P4 上运行
- 云端 LLM 只提供意图理解与深度对话，**不进实时感知决策回路**
- 本地视觉感知、本地运动决策、本地工具调度是评审加分点

### 4.2 硬件可靠性分层（2026-07 修订，随 04 D-017 与 IMU 换型同步）
- **Layer 1（碰撞/抬起）**：IMU **QMI8658**（顶替 ICM-42688-P，选型证据链见 06），片上 Tap / Wake-on-Motion 事件出中断
- **Layer 2（视觉感知）**：OV5647 MIPI-CSI 相机 + 本地 ESP-DL 推理
- **已砍掉**：多区 ToF（VL53L5CX）——速度慢不需要；**悬崖 IR（ITR20001×3）**——本版去掉（04 D-017），lift/碰撞由 IMU 兜底，桌沿风险靠低速运动约束
- 另有硬需求：**电机堵转过流保护**（电流采样 + 编码器不动 → STBY 急停，04 D-018）

### 4.3 开发铁律：能用现成不写 → 能 AI 不手搓 → 才手搓
- 视觉/语音/表情/对话/摄像头/联网优先用乐鑫官方且已支持 P4 的现成件（详见复用报告）
- 现成没有的先让 AI 出、人复核
- 只有"现成没有 + AI 不可靠 + 关系成败"的才亲手写（自研核心：本地决策状态机等 7 项）

### 4.4 双形态规划
- **V1（比赛 + 首发）**：一体式桌面机器人
- **V2（产品迭代）**："基座 + 取下挂坠"模式
- **V1 阶段不实现 V2**，外形上预留磁吸暗示

### 4.5 工具调用架构（混合方案）
- **本地工具**（必须本地，比赛加分）：运动、表情、传感器查询、本地视觉
- **局域网工具**：直调 Home Assistant REST API
- **互联网工具**（demo 用）：发邮件、查天气
- **MCP / MQTT broker / Apple 日历**：**比赛阶段不上**

## 5. 必须坚守的反面清单

| 不做 | 理由 |
|---|---|
| 纯云端 LLM 方案 | 违反"主要功能在 P4" |
| 全本地小模型 | 体验上不去 |
| 外挂安卓/树莓派副屏 | 桌面机器人不叠 SBC |
| ESP32 上做 CalDAV | 复杂度高无加分 |
| ESP32 上跑完整 MCP client | 协议层太重 |
| 毛绒外套带异形屏孔 | 视觉冲突，工程难 |
| 真做"取下挂坠"形态 | V1 工程量翻倍 |
| Arduino-ESP32 框架 | P4 完整 API 只有 ESP-IDF |
| **为"自己写"重写官方已有且支持 P4 的现成件** | **违反开发铁律，浪费完成度** |

## 6. 设计依据（市场/学术）

### 6.1 婴儿图式（Kindchenschema）
所有"萌"的设计遵循 Konrad Lorenz 1943 年婴儿图式七要素，按重要性：
1. 大、深陷的眼睛 2. 圆润的身体形状 3. 厚、大的头 4. 鼓起的前额 5. 圆鼓的脸颊 6. 短粗的四肢 7. 柔软的表面

**关键反规律**：拟人化（humanoid）会降低婴儿图式效果。NanoSoul 走"小生物形"，不走"小人形"。

## 7. 评审应答准备

### 7.1 必答：为什么用 P4 不用 S3？
| P4 能力 | S3 做不到 | NanoSoul 用法 |
|---|---|---|
| MIPI-DSI 2-lane×1.5Gbps + PPA + 2D-DMA | S3 只能 SPI/RGB，无 GPU | 大屏表情流畅渲染 |
| MIPI-CSI 摄像头 + ISP | S3 只有 DVP | **本地视觉感知主人（核心差异化）** |
| H.264 硬件编码 | S3 没有 | 实时视频流（esp_h264，1080P>30fps） |
| RISC-V 双核 400MHz + AI 指令 + FPU | S3 双核 240MHz | **本地小模型推理（esp-detection >18FPS@P4）** |
| 55 GPIO + 丰富 PWM | S3 45 GPIO | 三电机 + 多传感器同时跑 |
| USB 2.0 HS 480Mbps | S3 是 USB FS | UVC 摄像头/海量外设 |

### 7.2 必答：为什么必须有全向移动？
答：主动陪伴需要主动接近，桌面环境只有全向轮能在杂物间游走、贴近主人。这把全向移动从"装饰"变成了"功能本质"。
