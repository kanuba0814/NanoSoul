# 10 · 上板验证：SD 配置 + 烧录 + 读自检

> 整机固件（Phase 0–F）已全部板外 `idf.py build` 通过，**并已完成首轮上板 bring-up（实测记录见 §6）**。本文件是**持板者（Captain）上板要做的全部事**：备 SD 卡、烧录、按自检日志确认。软件侧的重试/定位由自检循环 + 执行者完成，你只负责刷机 + 回贴一段串口日志。

## 0. 硬件前提

- Waveshare **ESP32-P4-WIFI6** 开发板 + **MIPI-DSI 屏**（ST7701 480×640）+ **OV5647 相机**（MIPI-CSI）插好。
- **microSD 卡**插入板载卡槽（存配置 + 语音临时文件）。
- 电机/编码器/INA219/IMU/BH1750 **本版不接**（固件探测缺席自动降级，不影响启动）。
- 供电：开发板 USB 供电即可（电机不接，无需电池链）。

## 1. SD 卡准备

把 `sdcard_template/nanosoul/config.example.json` 拷到 SD 卡的 `/nanosoul/config.json`，按需填：

- **WiFi**：`wifi.ssid` / `wifi.password`（不填=离线，本地感知照跑）。
- **云端对话**：`chat.provider`（`anthropic` 或 `openai`）+ `base_url` + `api_key` + `model`。
- **语音**（可选）：`stt.*` / `tts.*` 填 OpenAI 兼容端点 + key。
- **上位机**：`companion.token` 改一个自己的口令。
- **运动**：`motion.enabled` 保持 `false`（没接轮）。
- **调试叠加**：`debug.overlay` 保持 `true`（屏上显示硬件/决策参数）。

> **真 key 只在 SD 卡上，不进仓库。**

## 2. 选启动模式并烧录

三种模式（`idf.py menuconfig` → NanoSoul → Boot mode，或改 sdkconfig）：

| 模式 | 用途 |
|---|---|
| `FACE`（默认） | 产品/演示：表情脸 + debug HUD + 全栈跑 |
| `SELFTEST` | **首次上板选这个**：全栈起来后跑自检循环，串口逐项 JSON |
| `TESTPANEL` | 旧三电机 LVGL 测试面板 |

```fish
source /home/gxxl/.espressif/v5.5.2/esp-idf/export.fish
idf.py menuconfig      # 选 SELFTEST（首次）
idf.py -p /dev/ttyACM0 flash monitor
```

`idf.py flash` 会一并写：app + emote 合包(emote_gen) + 人脸模型(human_face_det)。**16MB flash、分区表已重排，首刷会全擦**——确认卡上配置已备好再刷。

## 3. 读自检日志（SELFTEST 模式）

串口每轮每项输出一行 JSON，直接 grep：

```
{"st":"selftest","round":3,"item":"sd_mount","result":"PASS","pass":true,"manual":false,"detail":"..MB free"}
{"st":"selftest","round":3,"item":"camera_stream","result":"PASS",...,"detail":"+15 frames/round"}
{"st":"selftest","round":3,"item":"face_detect","result":"PASS",...,"detail":"6.1fps face=1 a0.09 fr0.71"}
...
{"st":"selftest_round","round":3,"fails":0,"cumulative_fails":0}
```

**判读**：
- `PASS` = 该项好；`SKIP` = 硬件缺席/未配置（**不算失败**，如没接电机的 `mic_record` 之外、没填 key 的 `llm_ping`）；`FAIL` = 要处理。
- 各阶段应绿的项（**共 28 项**，交互功能落地后新增 9 项）：
  - 底座 `sd_mount / config_parse / psram / partition_layout`；表情 `emote_mount / emote_render / hud_draw`；相机+人脸 `i2c0_probe / camera_stream / face_detect`。
  - **交互纯逻辑（恒绿，无硬件）**：`motion_ik / arbiter_sim / soul_sim / expr_sim / fusion_sim / imu_sim / prim_sim / stall_sim`——仲裁器/状态机/表情防抖/PC 融合/IMU 检测/运动原语/堵转 FSM 的逐条断言。
  - **交互传感探针**：`light_read`（BH1750）/ `imu_probe`（QMI8658 0x6A/0x6B）/ `touch_probe`（FT6x36 0x38）——接线则 PASS，未接 SKIP。
  - 联网 `wifi_connect / sntp / llm_ping`（无配置 SKIP）；音频 `codec_playback / mic_record`；上位机 `ws_loopback`。
- `wakenet_load` 标 MANUAL（本版能量 VAD，非 WakeNet）。

**回贴**：把连续几轮的 selftest JSON（尤其任何 `FAIL`）贴回来，剩下的定位/改码/出新固件由执行者做，不用你逐项试。

## 4. FACE 模式看什么

- 屏上：表情动画（默认 waiting/张望），顶部 6 行绿字 HUD（SOUL 状态 / FACE bbox / MOT 意图+duty / ENC / NET / FPS / HEAP）。
- 人走进相机视野：HUD 的 `FACE p1 x.. a.. f..` 跳动；由远及近 SOUL 依次 APPROACH→ENGAGE→RETREAT；正脸盯 1.5s→GAZED，表情切 `o`。**全程可断网**。
- 联网后：喊话（能量唤醒）→ 录音 → 云端 STT/对话/TTS → 扬声器回答，表情 waiting→think→waiting。
- 电脑连 `ws://nanosoul.local/ws?token=<你的token>`（浏览器控制台/websocat）：收到 1Hz `state` + 即时 `event` 流；发 `{"type":"ask","id":1,"text":"你好"}` 收到回复；发 `{"type":"estop"}` 进 FAULT。

## 5. 已知待办（上板后按需迭代）

- **相机方向**：屏物理旋转装法若上下/镜像反了，改 `components/face` 的 `FACE_ROTATE_CCW`（编译参数），半小时内可对好。
- **麦克风录音路径**：本板首次验证；`mic_record` 若 `rms≈0` 说明 ADC/AFE 增益或时钟要调（`components/audio` 的 `esp_codec_dev_set_in_gain` / mclk）。
- **C6 WiFi**：esp_hosted 用默认 SDIO 配置；`wifi_connect` 一直 SKIP/连不上则可能要按 Waveshare 板配 SDIO 引脚。
- **接电机时**：M1 的 IN1/IN2 占 IO24/25（=USB 串口），接线前要在 `BOARD_MAPPING` 里挪 M1 或改用 WS 遥测代替串口日志；然后 SD 配置 `motion.enabled=true` 才真转轮。
- **WakeNet 升级**：`srmodel` 分区已留；换掉 `components/voice` 的 `wake_detected()` 即可接 ESP-SR 唤醒词。

## 6. bring-up 实测记录（2026-07-05，v1.3 硅版，commit `baf909d`）

首轮上板结果：**13 PASS / 4 SKIP / 1 FAIL**。

- **PASS**：底座 4 项（`sd_mount/config_parse/psram/partition_layout`）、表情 3 项（`emote_mount/emote_render/hud_draw`，渲染 30fps）、相机与人脸（`i2c0_probe/camera_stream/face_detect`——OV5647 检出、800×1280 采集、检测 **8fps**）、决策纯逻辑（`motion_ik/soul_sim`）、`codec_playback`、`ws_loopback`。
- **SKIP**：`wifi_connect / sntp / llm_ping`（SD 未配 WiFi/key）、`wakenet_load`（MANUAL，本版能量 VAD）。
- **FAIL**：`mic_record` —— ES8311 ADC 静音（即 §5 第 2 条首验风险项，待查）。

断网状态下本地感知闭环（看到人 → 表情/运动意图响应）完整跑通。上板踩坑与修复已全部固化进 `sdkconfig.defaults` / 代码，复刷不会复现：

| 症状 | 根因 → 修复 |
|---|---|
| 开机断言循环 `mempool no mem` | esp_hosted SDIO mempool 抢内部 RAM → `CONFIG_ESP_HOSTED_MEMPOOL_PREFER_SPIRAM=y` |
| 无 WiFi 配置时 companion 起不来 | tcpip 栈未起 → `esp_netif_init()` 无条件早调 |
| `/dev/video0` 不注册 | 传感器驱动未编入 → `CONFIG_CAMERA_OV5647=y` |
| `ppa_do_scale` INVALID_ARG、帧全丢 | PPA 输出缓冲未按 cache line 对齐 → 128B 对齐分配 |
| HUD 刷屏 `no mem for mask_buf` | gfx label 未设尺寸（mask_buf=w×h）→ `gfx_obj_set_size` |
| 渲染帧计数恒 0 | `ALL_FRAME_DONE` 不触发 → 改 `ONE_FRAME_DONE` |
| 内部 RAM 吃紧 | emote 绘制缓冲移 PSRAM + `SPIRAM_MALLOC_ALWAYSINTERNAL=4096` |
