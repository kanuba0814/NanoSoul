# NanoSoul 工程流程与风险清单

> 单人负责制版本。流程按"**能用现成不写**"的复用路线组织：先白嫖官方现成件搭地基，再把自研核心接管上去。
> 每周更新"风险清单"和"待决问题"，已解决的归档到"决策记录"。

---

## 1. 复用优先的五阶段路线（核心节奏）

> 思路：先用现成件把"地基 + AI 子系统 + 视觉"快速拼起来，把省下的时间全投到自研的本地决策状态机上。每阶段有明确"晋级阈值"，达标才进下一阶段。
>
> **进度（2026-07-05）**：阶段 1–3 与阶段 4 主干已经由 docs/08 的 Phase 0–F 落地并上板实测（表情/视觉/决策/联网/语音/上位机全栈，实测基线见 docs/00 §4）。剩余 = 接轮后的 PID/里程计、传感三件套接入、堵转保护闭环与阶段 5 打磨项（差距清单见 docs/00 §5）。

### 阶段 1 — 地基（先打通硬件抽象层）
- 拉 Waveshare ESP32-P4-WIFI6 板厂 demo + ESP32-P4-Function-EV-Board 官方示例
- 跑通：MIPI-DSI 屏（esp_lvgl_port，先软渲染）+ esp_video 摄像头出图 + ESP32-C6 联网（esp_hosted）
- **晋级阈值**：屏能刷 LVGL、摄像头能出图、C6 能连 WiFi

### 阶段 2 — 白嫖 AI 子系统
- 拉 ESP-Brookesia `examples/agent/chatbot`，填 Coze/OpenAI 凭证 → 表情 + 唤醒 + VAD + 云对话 + MCP 开箱即用
- 按需叠加 ESP-SR 做本地唤醒/命令词
- **晋级阈值**：能唤醒、能对话、表情会动

### 阶段 3 — 视觉感知
- 拉 ESP-WHO 人形检测（pedestrian_detect）+ 人脸检测，改 BSP 适配 OV5647
- **晋级阈值**：稳定输出"主人在画面中的位置/距离估计"

### 阶段 4 — 自研核心（集中精力）
- 本地感知决策状态机：消费视觉/IMU/光照 → 驱动底盘 + 表情（断网可跑）
- 三轮运动学 + PID + QMI8658 事件接入（现成驱动）+ IP5306（载板阶段）——ICM-42688 SPI 与 ITR20001 已出清单（IMU 换型见 06、悬崖砍掉见 D-017）
- **改变阈值**：PPA 在 9.4 不稳 → 回退软渲染；CSI 偶发崩溃 → 开 IRAM cache-safe + 确认 P4 v3.x 硅版；模型精度不足 → 缩类别/降帧率重训

### 阶段 5 — 集成打磨
- OTA、WebUI、视频流（esp_h264）、断网降级、电量显示
- 断网演示多网络环境压测、备用录屏、PPT、答辩词
- **demo 前一周不加新功能**

## 2. 强制纪律

### 2.1 必须做
- **每写一行前过三级过滤**：能用现成不写 → 能 AI 不手搓 → 才手搓
- **每个新外设上 PCB 前先面包板单独 bring-up**：PCB 上调 bug 成本是面包板 10 倍
- **写代码前先读 SKILL.md**：`/mnt/skills/user/embedded-hw-selection/SKILL.md`（三个 Gate）
- **commit 前跑 `idf.py build`**，主干必须能编译
- **AI 一切产出人必复核**

### 2.2 必须不做
- 不在主干放硬编码密钥/Token
- 不在 demo 前一周加新功能
- 不依赖外接 SBC、副屏、外置 AI 加速器
- 不为"自己写"而重写官方已有且支持 P4 的现成件

## 3. 风险清单（按严重度）

### 3.1 HARD STOP 级（发生立刻停下解决）

| 风险 | 触发条件 | 应对 |
|---|---|---|
| **单人带宽不足，完成度塌方** | P0 进度持续落后路线表 | 立即再砍功能到 P0 最小集，杂事全外包，核心只保"断网感知闭环" |
| **P4 MIPI-CSI 摄像头跑不起来/崩溃** | OV5647 不出图、偶发 CSI 0x102 崩溃 | **已解**（2026-07-05）：v1.3 硅版实测稳定——`ISR_CACHE_SAFE` + LDO_VO3@2500mV 补丁 + `CONFIG_CAMERA_OV5647` 编入，见 docs/10 §6 |
| ~~悬崖传感器全部失效~~ | —（悬崖已砍，D-017） | IMU 兜底 lift/碰撞；桌沿风险靠低速运动 + 演示场地防护 |
| 电机供电不稳，板子复位 | 启动浪涌致 5V 跌落 | 加大电解电容，分离电源域 |
| MIPI-DSI 屏跟 P4 时序不匹配 | 花屏/不显示 | 换 Waveshare 推荐型号 |
| WiFi 在演示场地失效 | 决赛网络不可控 | 手机热点 + 本地兜底；**断网演示本就是卖点，反而稳** |
| 主控仅做 IO 不做核心功能 | 评审判违规 | 确保 ESP-DL 本地推理 + 本地决策状态机在跑 |

### 3.2 严重风险（主动监控）

| 风险 | 监控 | 应对 |
|---|---|---|
| **LVGL PPA 加速实验性、9.4 不稳** | 盯 esp_lvgl_port/LVGL issue | 软件渲染 fallback（已留） |
| **两芯配网（C6+esp_hosted）非原生 P4** | 按 esp-hosted 文档逐步配 | network_provisioning 手动适配，留 SoftAP 兜底 |
| ~~ICM-42688-P 无官方 SPI 驱动~~ | 已消解 | IMU 换 QMI8658（06），SensorLib/官方 registry 组件现成 |
| **麦克风录音路径静音** | bring-up 实测 `mic_record` FAIL（ES8311 ADC 无声） | 调 in gain / mclk / AFE（docs/10 §5）；语音链路当前唯一断点 |
| **表情/手势模型自训精度/帧率不足** | esp-detection 自测 mAP/FPS | 缩类别、降输入分辨率、降采样频率 |
| LLM API 延迟过高 | 测试记录 | 本地兜底句 + 边缘网关 |
| 电池续航不够 demo | 全负载测试 | 加大电池或备充电线 |
| VL53L5CX 已砍但代码遗留 | grep 全库 | 清理 P0.2 遗留 |
| 演示场地光线干扰摄像头 | 现场预演 | 调 ISP 自动曝光 |

### 3.3 中等风险

| 风险 | 应对 |
|---|---|
| 全向轮打滑 | 硅胶轮面 + 加重底盘 |

| D-007 | 表情走 LVGL v9.4 + PC 模拟器开发 | 不依赖真机 |
| D-008 | 婴儿图式作为外形设计准绳 | 科学+市场双验证 |
| D-009 | 比赛阶段一体式，不做挂坠 | 工程量翻倍无加分 |
| D-010 | 毛绒做"披肩"不做"屏孔外套" | 屏与毛绒视觉冲突 |

| **D-013** | **开发铁律：能用现成不写 → 能 AI 不手搓 → 才手搓** | 单人保完成度 |
| **D-014** | **视觉/语音/表情/对话/摄像头/联网全用官方现成件** | 已验证支持 P4 |
| **D-015** | **流程按复用五阶段路线推进** | 先白嫖现成，省时间投自研核心 |

## 6. 答辩准备清单

### 6.1 必备话术（宪法 7.1, 7.2）
- 为什么用 P4 不用 S3：6 大不可替代能力 + 三件套量化对比
- 为什么必须全向移动：主动陪伴 = 主动接近
- 为什么不用云端全权决策：本地编排 + 本地视觉是核心

### 6.2 演示脚本（决赛前一周敲定）
- 1 分钟：唤醒 + 自我介绍 + 表情切换
- 1 分钟：本地视觉感知（人脸 + 表情识别）
- 1 分钟：对话 + 工具调用（控灯 / 发邮件）
- 1 分钟：堵转/抬起保护 + 紧急停车（悬崖已砍：演示 IMU 抬起检测 + estop 急停）
- 30 秒：自主行为（看到主人低头很久主动凑过去）
- 30 秒：双形态愿景（V2 挂坠概念 PPT）
- **核心**：现场断 WiFi，本地感知决策闭环照常跑

### 6.3 备用 demo
- 录屏视频现场展示
- "PC 模拟器版"作备份
