# 11 · NanoSoul 上位机（Companion Console）需求规格 v1 —— 外包实现版

> 甲方 = NanoSoul 项目方；乙方 = 受托实现方。
> **本文件自包含**：设备侧协议全文在附录 A（已与设备固件实测逐字核对），乙方无需访问项目仓库即可实现。
> 协议 v1 已冻结。乙方**不得假设任何未写明的设备行为**；发现文档与实际不符，报甲方裁决（见 §10），不要自行猜测兼容。

---

## 0. 一句话

给 NanoSoul 桌面陪伴机器人做一个**局域网上位机**：连 WebSocket，实时展示机器人内部状态与「主人状态」事件流，提供对话 / 遥控 / 快照 / 系统命令，**并把本机（用户电脑）状态采集后上报给机器人，作为它的一路感知输入**，同时支持录制导出数据。**机器人端已全部实现并上板实测，本工程只做 PC 侧**，不涉及任何固件改动。

## 1. 背景（只讲乙方需要知道的）

NanoSoul 是一台 ESP32-P4 桌面陪伴机器人：本地视觉感知（人脸检测 8fps）驱动一个 9 态行为状态机（`soul`），控制表情脸与运动意图；云端 LLM 只做对话。设备在 LAN 内开 WebSocket 服务：

- 地址 `ws://nanosoul.local/ws?token=<口令>`（mDNS）或 `ws://<设备IP>/ws?token=<口令>`，端口 **80**，明文 ws（无 TLS）。
- 设备 → PC：**1Hz 全量 `state` 心跳** + **即时 `event` 帧**（7 种）+ **二进制 JPEG 快照**。
- PC → 设备：**9 种 JSON 命令**，逐条回 `ack`。

上位机的双重用途，优先级相同：

1. **比赛演示**：投影给评委看——界面要干净、直观、断连不难看。
2. **日常调试**：信息全、可记录、可导出。

## 2. 范围

**做**：单个设备的连接、可视化、控制、**PC 状态采集上报（F11）**、录制导出，及配套模拟器（见 F10）。
**不做**：固件/设备侧任何改动、云服务、手机端、公网访问、账号体系、数据库（本地文件即可）、多设备同时管理（预留即可，见 F1.5）。

## 3. 交付形态与技术约束

| # | 约束 |
|---|---|
| T1 | 运行形态二选一：**浏览器单页应用**（本地静态文件或一条命令起本地静态服务）或**跨平台桌面应用**。必须能在 **Linux** 运行（甲方主力环境 Fedora）；Windows 兼容为加分项 |
| T2 | 若为浏览器形态：页面须经 **http:// 或 file://** 打开——设备是 `ws://`（非加密），https 页面会被浏览器混合内容策略禁止连接 |

## 4. 功能需求

> 每条带编号，验收逐条对（§7）。未标注者均为必须项；标 **[加分]** 的不计入验收底线。

### F1 连接管理

- F1.1 连接面板：地址输入（预填 `ws://nanosoul.local/ws`）、token 输入、连接/断开按钮。支持直接输 IP（mDNS 解析依赖操作系统，不可作为唯一手段）。
- F1.2 连接状态常驻可见：未连接 / 连接中 / 已连接 / 重连中（含下次重试倒计时）。
- F1.3 **自动重连**：指数退避（1s 起，上限 10s，带抖动），手动断开则不重连。
- F1.4 **数据新鲜度看门狗**：已连接但 **>3s 未收到 `state`** → 界面标「数据停滞」，并提示两种可能：链路异常，或**超出设备 3 客户端广播上限**（见 §6-G）。
- F1.5 [加分] 连接历史下拉（最近 5 个地址）；多设备切换预留（单活跃连接即可）。
- F1.6 收到**未知 `type` 帧必须静默忽略**（协议前向兼容铁律，附录 A）。未知字段同理。

### F2 状态仪表盘（消费 `state`，1Hz）

- F2.1 **soul 状态机视图**：11 态（枚举与含义见附录 C）以图形呈现，高亮当前态；最近 N 次跳变（来自 `soul_transition` 事件）以轨迹/列表展示。FAULT 态整块变红。
- F2.2 **人脸感知视图**：在 −1..+1 归一化画布上画十字标（`face.cx/cy`）+ 按 `face.area` 的圆圈 + `frontal` 数值；`present=false` 显示「无人」。
- F2.3 **运动视图**：意图 `intent[vx,vy,wz]` 矢量图 + 三轮 `duty[3]`（有符号，±1023）柱状 + `enabled` 开关态醒目标注（false 时标「未接轮，仅计算」）。
- F2.4 **数值区**：`emotion`、`enc_rpm[3]`、`current_ma`（`null` 显示「未接」）、`net.ip/rssi`（ip 为空串 = 未联网）、`llm`、`voice`、`heap`、`fps.render/detect`。
- F2.5 **时序曲线**（滚动窗 ≥120s）：`fps.detect`、`fps.render`、`heap`、`face.area`、`enc_rpm[3]`。
- F2.6 `ts` 是**设备开机毫秒**：检测到 ts 回退 → 界面提示「设备已重启」，曲线断开而非连线。

### F3 事件流与陪伴统计（消费 `event`）

- F3.1 事件滚动日志：本机接收时间 + 设备 ts + name + data 摘要；`fault` 红色高亮并弹出常驻横幅（直到 `clear_fault` 成功或 soul 离开 FAULT）。
- F3.2 `llm_reply.text` 在对话面板展示（F4）；**渲染前清洗非法 UTF-8 尾部**（见 §6-E）。
- F3.3 **自检矩阵**：把 `selftest_item` 事件按 `name`×`round` 聚合为 PASS/FAIL/SKIP 网格。注意：该事件**仅设备运行 SELFTEST 固件模式时才出现**（§6-I），无数据时显示空态说明，不是 bug。
- F3.4 **陪伴统计（本次会话内）**：从事件流实时聚合——在席时长与在席率（`face_present`/`face_lost`）、被注视次数（`gazed`）、语音唤醒次数（`wake`）、对话轮数（`llm_reply`）、fault 次数、soul 各状态时长占比（`soul_transition`）。会话 = 一次连接期间；跨会话长期分析 [加分]（基于 F9 录制文件离线计算）。

### F4 对话面板

- F4.1 文本输入 → 发 `ask{text}`；输入框按 **UTF-8 字节数**校验长度（整帧 <2048 字节，见 §6-D），超限阻止发送并提示。
- F4.2 会话流展示：己方消息 → `ack`（受理/失败）→ 异步 `llm_reply` 回复（云链路，可能数秒）。**30s 无回复标「未响应」但不判错**。
- F4.3 `ack.ok=false` 时展示 `err` 文本。

### F5 遥控（安全第一）

- F5.1 虚拟摇杆或方向键操控，输出 `teleop{vx,vy,wz,ttl_ms}`，三值限幅 **[-1,1]**，发送频率 5–10Hz（按住期间持续重发）。
- F5.2 **上位机必须自带 deadman**（不依赖设备）：控件释放**立即**发一帧全零；断连/切页/失焦停止发送前也先发全零（尽力而为）。理由见 §6-C：设备当前**不实现 ttl_ms 自动停**。
- F5.3 `motion.enabled=false` 时设备回 `ack ok:false err:"motion disabled"`——UI 把遥控区置灰并显示该原因，不再连发。
- F5.4 **急停按钮常驻可见**（所有页面/布局下都在），点击即发 `estop`，**不得有确认弹窗**；支持键盘快捷键（建议 Esc）。`clear_fault` 则需二次确认。
- F5.5 真机上 teleop 与设备本地决策的仲裁属固件后续工作（§6-C）：本工程验收 teleop 以**模拟器 + 真机「motion disabled 拒绝」路径**为准，不验收真机实走。

### F6 快照

- F6.1 按钮发 `get_snapshot` → 展示返回的二进制 JPEG（当前检测帧，300×480 竖向）。
- F6.2 时序与缺帧处理见 §6-B：二进制帧先于 `ack` 到达；**`ack ok:true` 不保证有图**——发出后 1.5s 未收到二进制帧即判「本次无图」，UI 提示可重试。
- F6.3 一键保存 JPEG 到本地（文件名含本机时间戳）。[加分] 定时连拍（≥2s 间隔）。

### F7 表情控制

- F7.1 表情下拉**限定 5 个合法值**：`waiting / o / sad / sleep / think`（附录 C）+ 模式 `now|fade`，发 `set_emotion`。
- F7.2 设备**不校验 name**、ack 恒 ok（§6-F），所以 UI 侧限定取值就是唯一防线，不得提供自由文本输入。
- F7.3 提示文案：覆盖 10s 后自动回归状态机。

### F8 系统命令

- F8.1 按钮组：`clear_fault`（需确认）、`config_reload`、`set_overlay{on}`（开关设备屏上 debug HUD）、`selftest`。每条命令展示 ack 结果。
- F8.2 `selftest` 的 ack 为 `ok:true, err:"see serial"`——这是**说明文字不是错误**（§6-A），UI 原样展示「结果见设备串口」。

### F9 记录与导出

- F9.1 「录制」开关：开启后把**全部收发帧**写入 JSONL——每行 `{t_local:<ISO8601 本机时间>, dir:"rx"|"tx", frame:<原始 JSON>}`；二进制快照另存文件、行内记文件名。
- F9.2 一键导出（下载/保存）。录制文件**不含 token**（T5）。
- F9.3 [加分] 录制文件回放模式（脱机重演仪表盘）。

### F10 协议模拟器（乙方交付物，也是验收工具）

- F10.1 一个本地 WebSocket 服务端（`ws://localhost:<port>/ws`），**逐字忠实**实现附录 A 的设备侧行为，包括：token 校验（含空 token 放行）、1Hz state、event、9 命令的 ack 语义（含 `motion disabled` 可切换、`set_emotion` 恒 ok、snapshot 先二进制后 ack、`selftest` 的 `err:"see serial"`）、ack 无 `v/ts`、`llm_reply` 文本 160 字节截断、**第 4 个客户端可连但不广播**。
- F10.2 场景脚本（命令行参数或控制台选择）至少含：① 在席/离席循环（face_present/lost + face 数值渐变 + soul 流转 IDLE→APPROACH→ENGAGE→RETREAT）；② GAZED 触发；③ 一轮对话（ask→延迟 2s→llm_reply）；④ fault 注入与恢复；⑤ SELFTEST 模式（周期发 19 项 selftest_item）；⑥ 设备重启模拟（断开 + ts 归零重连）。
- F10.3 [加分] 丢帧/延迟注入。
- F10.4 模拟器须**接收并打印 `pc_state` 帧**（附录 A.4），供 F11 自测；并提供「老固件怪癖模式」开关——对未知 type 回 `ack {id:0, ok:false, err:"unknown cmd"}`，用于验证上位机对无法关联 id 的 ack 静默忽略（§6-L）。

### F11 PC 状态采集与上报（机器人的一路感知输入）

- F11.1 按附录 A.4 的 schema 周期上报本机状态：**变化即发 + 5s 心跳**；连接断开期间停止采集或丢弃均可，重连后立即发一帧全量。
- F11.2 采集项与来源（Linux 必须，Windows 加分）：
  - `activity` / `idle_s`：系统输入空闲时长（Linux：X11 XScreenSaver 扩展或 Wayland idle-notify 协议，桌面环境差异需在 D1 说明书标注实测范围；Windows：`GetLastInputInfo`）。
  - `locked`：锁屏/屏保状态（DBus `org.freedesktop.ScreenSaver` 或等价）。
  - `focus`：前台应用 → 类别映射（`work|meeting|media|browse|comm|other|unknown`）。**映射表在本机完成且用户可编辑**（简单配置文件即可）；取不到前台信息时报 `unknown`，不得报错。
  - `media`：是否有音频/视频正在播放（取不到则恒 false 并在 UI 标注「不支持」）。
  - `dnd`：UI 上的手动勿扰开关（**必须做**——自动检测不可靠时用户能一键让机器人安静）。
- F11.3 **隐私为硬性验收项**：上报内容仅限 schema 中的枚举与秒数；窗口标题、URL、应用名、按键内容**不得出现在任何出站帧、日志与录制导出中**；应用名→类别映射只存在于本机。
- F11.4 透明度 UI：常驻小指示区实时显示「正在上报什么」（当前 activity/focus/dnd）；**总开关**（关闭后完全停发 `pc_state`）；分项开关（如关闭 focus 采集 → 恒报 `unknown`）。
- F11.5 [加分] `focus:"meeting"` 的自动检测（会议应用前台或摄像头/麦克风被其他应用占用）；做不了自动检测时，`dnd` 手动开关即为兜底，不影响验收。

## 6. 设备侧已知实现细节（乙方必读，防坑清单）

以下是**设备固件实测行为**，其中部分未写入协议正文，按此实现：

- **A. ack 帧无 `v`、无 `ts`**，形如 `{"type":"ack","id":1,"ok":true}`；`err` 字段可选且**语义是说明文字**——`ok` 才是成败判据（例：`selftest` 回 `ok:true` 且 `err:"see serial"`）。命令未带 `id` 或非数字时设备按 `id:0` 回。
- **B. snapshot 时序**：二进制 JPEG **先**发、`ack` 后发，且二进制只发给请求方（state/event 是广播）。相机取帧失败时**只回 ack、没有二进制帧**——必须超时兜底。
- **C. teleop**：协议字段含 `ttl_ms`，**但当前固件不实现到期自动停**（照发该字段，为后续固件保留）；且设备本地决策任务每 100ms 会覆写运动意图，真机遥控仲裁属固件后续工作。上位机侧 deadman（F5.2）**无条件必须做**。
- **D. 入站命令帧上限 2048 字节**，超限设备静默丢弃（连 ack 都没有）——所以 F4.1 必须在 UI 侧限长。
- **E. `llm_reply.text` 设备侧截断为 160 字节**，可能切在多字节 UTF-8 字符中间——渲染与导出前清洗非法尾部字节。
- **F. `set_emotion` 设备不校验 name**，任何字符串都回 `ok:true`；合法值只有附录 C 的 5 个。
- **G. 客户端上限 3**：第 4 个连接**握手会成功、命令有 ack**，但**收不到 state/event 广播**——这就是 F1.4 看门狗存在的原因。
- **H. token**：设备配置的 token 为空时放行一切连接；token 不匹配在**握手层直接拒绝**（表现为 WebSocket 连接失败，无错误详情）——UI 提示应包含「检查 token」。
- **I. `selftest` 命令不回 WS 结果**（结果走设备串口）；`selftest_item` 事件仅设备固件处于 SELFTEST 模式时才会持续出现。
- **J. `ts` = 设备开机毫秒**，重启归零；`net.ip` 为空字符串表示未联网（此时 `rssi` 无意义）。
- **K. 设备不发 WS ping**；活性判据就是 1Hz state（F1.4）。
- **L. 老固件对未知 type 回 `ack {id:0, ok:false, err:"unknown cmd"}`**——上位机发送 `pc_state` 后可能收到这种 ack。规则：**无法按 id 关联到已发命令的 ack 一律静默忽略**（识别 `pc_state` 的固件版本不回 ack）。

## 7. 验收

### 7.1 模拟器验收（乙方环境演示）
F1–F11 逐条过，全部必须项通过；§6 防坑清单逐项抽查（甲方会故意用模拟器触发 B/D/E/G/L 等边界）。F11 验收要点：模拟器端看到 `pc_state` 随本机真实动作变化（停手 60s → idle；锁屏 → locked；切开关 → 停发/恒 unknown）；导出的录制文件中翻查不到任何窗口标题/应用名。

### 7.2 真机联调验收（甲方场地，约 1 小时）
1. 连接真机（token 正确/错误各一次）→ state 仪表盘全字段有值。
2. 人走进/离开相机视野 → F2.2 十字标跟随、F3 事件与 F3.4 统计正确累计。
3. 正对注视 1.5s → `gazed` 事件 + soul 进 GAZED。
4. `ask` 一轮 → ack + `llm_reply` 上屏（需设备已配云端 key）。
5. `get_snapshot` → 出图并保存。
6. `teleop`（设备未接轮）→ 界面按 F5.3 置灰并显示 "motion disabled"。
7. `estop` → 设备进 FAULT、横幅出现；`clear_fault` → 恢复。
8. `set_emotion` 5 值轮换、`set_overlay` 开关 HUD、`config_reload`。
9. 录制以上全过程 → 导出 JSONL 完整、无 token。
10. 设备重启 → 上位机自动重连 + 「设备已重启」提示。
11. `pc_state` 上报开启（若当期固件已消费该帧：设备遥测/HUD 出现 pc 信息；若尚未消费：确认设备回的 `unknown cmd` ack 被静默忽略、不污染 UI）。

### 7.3 稳定性验收
N1 与 N2 按 §5 执行，甲方复测。

## 附录 A 协议全文（v1 冻结，已对设备实测核对）

### A.1 传输与握手

- `ws://<host>/ws?token=<token>`，端口 80，仅局域网，明文 WebSocket。
- token 在 HTTP 升级握手时校验：设备侧未配置 token（空）→ 放行；不匹配 → 握手失败。
- 文本帧 = UTF-8 JSON；二进制帧 = JPEG。设备→PC 信封：`{"v":1,"type":"<kind>","ts":<开机毫秒>,...}`（**例外：ack 无 v/ts**）。
- **前向兼容铁律**：未知 `type`、未知字段一律忽略，不得报错。字段只增、不改语义。

### A.2 设备 → PC

**`state`（1Hz 全量心跳，广播给前 3 个客户端）**

| 字段 | 类型 | 语义 |
|---|---|---|
| `soul` | string | 当前状态名，9 值见附录 C |
| `emotion` | string | 当前表情名（5 值，附录 C） |
| `face.present` | bool | 画面中是否有人脸 |
| `face.cx` `face.cy` | float −1..+1 | 最大人脸中心（归一化，0=画面中心） |
| `face.area` | float 0..1 | 人脸 bbox 面积占比（距离代理，越大越近） |
| `face.frontal` | float 0..1 | 正脸程度（凝视代理） |
| `motion.intent` | [vx,vy,wz] float −1..1 | 机体系速度意图 |
| `motion.duty` | [int×3] −1023..1023 | 三轮有符号占空比（计算值） |
| `motion.enabled` | bool | false = 只计算不驱动电机 |
| `enc_rpm` | [int×3] | 三轮编码器转速（电机轴 RPM） |
| `current_ma` | int \| null | 电机总电流 mA；null = 电流计缺席 |
| `net.ip` | string | 空串 = 未联网 |
| `net.rssi` | int | WiFi 信号（未联网时无意义） |
| `llm` | string | `idle` / `busy` |
| `voice` | string | `idle` / `listen` / `think` / `speak` |
| `heap` | int | 空闲内部内存（字节） |
| `fps.render` `fps.detect` | float | 表情渲染 / 人脸检测帧率 |

样例见附录 B.1。

**`event`（即时，广播）**：`{"v":1,"type":"event","ts":...,"name":"<name>","data":{...}}`

| name | data | 含义 |
|---|---|---|
| `soul_transition` | `{from,to}` | 行为状态流转 |
| `face_present` / `face_lost` | `{}` | 主人在席 / 离席 |
| `gazed` | `{}` | 一次「被注视」触发 |
| `wake` | `{}` | 语音唤醒 |
| `llm_reply` | `{text}` | 一轮对话回复（≤160 字节，可能截断，见 §6-E） |
| `fault` | `{text}` | 故障（含 estop） |
| `selftest_item` | `{name,result,detail,round}` | 自检项结果（仅 SELFTEST 模式） |

**`snapshot`（二进制，仅发给请求方）**：一帧 JPEG（当前检测帧 300×480），响应 `get_snapshot`；先二进制后 ack，可能缺帧（§6-B）。

### A.3 PC → 设备（命令与 ack）

命令：`{"v":1,"type":"<cmd>","id":<n>,...}`（整帧 <2048 字节）。设备回 `{"type":"ack","id":<n>,"ok":bool[,"err":"<说明>"]}`。

| cmd | 字段 | 行为 |
|---|---|---|
| `ask` | `{text}` | 入队文字问答（队列深 4）；ok=已受理；回复异步走 `llm_reply` |
| `set_emotion` | `{name, mode:"now"\|"fade"}` | 表情覆盖 10s 后回归；**不校验 name**，UI 侧限 5 值 |
| `teleop` | `{vx,vy,wz,ttl_ms}` | 仅 `motion.enabled=true` 受理，否则 `err:"motion disabled"`；ttl 设备端暂未实现（§6-C） |
| `get_snapshot` | `{}` | 回二进制 JPEG + ack |
| `estop` | `{}` | 立即进 FAULT 急停锁定 |
| `clear_fault` | `{}` | 解除 FAULT |
| `config_reload` | `{}` | 设备重读 SD 配置 |
| `set_overlay` | `{on:bool}` | 开关设备屏上 debug HUD（缺 on 视为 true） |
| `selftest` | `{}` | ack `ok:true, err:"see serial"`，结果不走 WS |
| 其他 | — | `ok:false, err:"unknown cmd"` |

### A.4 PC → 设备：状态上报 `pc_state`（v1.1 增补，无 ack）

```json
{"v":1, "type":"pc_state", "ts":<上位机毫秒>,
 "activity":"active",   // active(有输入) | idle(无输入) | locked(锁屏/屏保)
 "idle_s":37,            // 距最后一次输入的秒数
 "focus":"work",         // work|meeting|media|browse|comm|other|unknown
 "media":false,          // 是否正在播放音视频
 "dnd":false }           // 手动勿扰
```

节奏：变化即发 + 5s 心跳；设备侧 15s 未更新视为无 PC 信息。识别该帧的固件不回 ack；老固件回 `unknown cmd` ack（§6-L，忽略）。隐私边界见 F11.3。

## 附录 C 枚举表

**soul 11 态**（v1.1 加法：末尾追加 LIFTED/DOZE，前 9 态语义不变）：`IDLE` 待机（无人）· `ENGAGE` 合适距离陪伴 · `APPROACH` 靠近（人远）· `RETREAT` 退后（人过近）· `GAZED` 被注视→害羞退避 · `LISTEN` 听（语音会话）· `THINK` 思考（等云端）· `SPEAK` 说话 · `FAULT` 故障锁定（estop/堵转等，运动清零）· `LIFTED` 被抬起（运动冻结）· `DOZE` 暗光瞌睡。前向兼容铁律：上位机对未知状态名按原名显示即可。

**emotion 5 值**：`waiting`（待机/张望，缺省）· `o`（惊讶）· `sad`（难过/故障）· `sleep`（睡眠）· `think`（思考）。

**llm**：`idle` / `busy`。**voice**：`idle` / `listen` / `think` / `speak`。
