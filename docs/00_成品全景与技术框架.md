## 1. 最终成品定义

### 1.1 一句话定位（引自宪法 01）

> NanoSoul 是一台具备主动感知能力的桌面陪伴机器人。基于 ESP32-P4 的视觉、运动和图形性能，它能在**本地**识别主人的存在、表情与行为，自主决策何时该陪伴、何时该退后；结合云端大模型实现深度对话，并通过工具调用接入家居生态。

硬约束（嵌赛/乐鑫赛道，详见 01）：**主要功能代码必须运行在乐鑫芯片上**——所有决策性逻辑在 P4 本地跑，云端 LLM 只做深度对话、不进实时感知决策回路。杀手锏 = 现场**断网**演示本地感知决策闭环。

### 2.2 硬件：一套固件目标、三种载体

固件**只对着无 PCB 模块版写**（CLAUDE.md 固件节 = 接线真值）；洞洞板是它的「焊死固化」；载板是后续目标。三者引脚有**刻意分叉**，互相不纠正（BOARD_MAPPING.md 已划清）。

| 载体 | 状态 | 要点 |
|---|---|---|
| **无 PCB 杜邦版**（当前实物） | ✅ 在用 | 现成模块 + 杜邦线；双电源（电脑 USB 供开发板、1S 电池→XL6009 升 5.9V 只带电机）**必须共地**；红/蓝母排干线 + 星地（锚点 XL6009 OUT−），防「电机一转 VM 塌到 1.3V」复发。细节见 `docs/应急方案_无PCB/` |
| **perfboard 洞洞板** | 📐 就绪待焊 | 7×9cm 24×30 孔，引脚与固件**零改动**；`perfboard/layout.py` 单一真值源（自带 DRC，出 4 图+接线表） |
| **载板 PCB** | 📐 设计定稿 | **62×72mm 4 层**（Ø88/R44 四边切平），DRC **0 违规/0 未连/0 parity（零 ignore）**；`pcb/circuit/geom.py` 是唯一几何真值。⚠️ `pcb/output/fab/` 现存 Gerber/CPL 是 6/30 旧 2 层大板导出的，**下单前必须重导**（BOM 已过嘉立创核对可沿用：U6→QMI8658A C3021082、R9→1206 C375525） |

三处引脚分叉（真值 = BOARD_MAPPING.md）：

| 项 | 无 PCB 模块版（固件现状） | 载板版（后续） |
|---|---|---|
| IMU QMI8658 | **I²C1**（模块无 CS 脚），INT=IO23 | **4 线 SPI**：SCLK=IO51/MOSI=IO50/MISO=IO49/CS=IO22 |
| 电机 STBY | **分置**：M0/M1 桥=IO51、M2 桥=IO52（固件同拉同放） | **共用单网** IO33（10k 下拉） |
| 电机电流 | **INA219**（I²C1 0x40） | 板载 **shunt→ADC**（IO52/ADC2_CH3）+ PTC 1.5A |

### 2.3 计算平台与板载资源

Waveshare **ESP32-P4-WIFI6**（v1.3 硅版实测）：16MB flash（QIO）/ 32MB PSRAM（200MHz，XIP）/ ESP32-C6 协处理（WiFi6，SDIO esp_hosted）。板载外设（引脚宏见 `components/bsp/bsp_pins.h`）：

- **屏**：ST7701S 480×640 竖屏，MIPI-DSI 1-lane@700Mbps。
- **相机**：OV5647，MIPI-CSI，SCCB@I²C0 0x36。⚠️ CSI 与 DSI 共用 MIPI DPHY 电源轨，靠 `cmake/patch_esp_video_ldo.cmake` 把 esp_video 补丁到 **LDO_VO3@2500mV**，否则相机不上电。
- **音频**：ES8311 codec（I²C0 0x18，I2S0）+ NS4150B 功放（PA_EN=IO53），16kHz/16bit/mono 全双工。
- **SD**：**SDSPI 模式**（CLK=IO43/MOSI=IO44/MISO=IO39/CS=IO42），LDO_VO4 供 IO 轨。
- **I²C0**（IO7/IO8）：板载三客户（codec/触摸/相机 SCCB），`board_i2c0` 组件统一建总线；**I²C1**（IO20/IO21，100kHz）：外接传感三件套。

### 2.4 固件架构（18 组件 + main）

ESP-IDF v5.5.2，`idf.py set-target esp32p4`。分层：

| 层 | 组件 | 职责一句话 |
|---|---|---|
| 地基 | `telemetry` | 全局遥测快照（mutex 保护）+ esp_event 事件总线，所有组件的汇聚点 |
| | `storage_sd` | SDSPI 挂卡 + `/sdcard/nanosoul/config.json` 字段级 overlay 配置（缺卡用内建默认） |
| | `bsp` / `board_i2c0` | 板载固定引脚宏 / I²C0 总线单例 |
| | `selftest` | 自检注册表 + 循环跑批，每项一行 JSON 到串口（19 项，见 §4） |
| 感知 | `camera` | esp_video(V4L2) 采 800×1280 RGB565 → PPA 全 FOV 降采样 300×480 → 帧回调；硬件 JPEG 快照 |
| | `vision` | ESP-DL 人脸检测（C++），产出 `tel_face_t{present,cx,cy,area_ratio,frontal_score}` |
| 决策 | `soul` | 10Hz 状态机：人脸观测 + 外部刺激（语音会话/故障）→ motion intent + face 情绪 |
| 表达 | `face` | emote 播放器薄封装：点屏、90° 旋转 flush、挂 `emote_gen` 分区、切换队列 |
| | `hud` | 遥测 6 行叠层（SOUL/FACE/MOT/ENC/NET/FPS），让没接的外设参数也可见 |
| 运动 | `motion` | 全向 IK + 输出闸：disabled 只算 + 发遥测；enabled 才经回调驱 `drv_motor` |
| 语音 | `audio` / `voice` | ES8311 录放 / wake→录音→STT→chat→TTS→播 全流水线（半双工） |
| 云 | `llm` / `dialog` | 双协议 chat + STT/TTS 客户端 / 单轮对话编排（voice 与上位机 ask 共用） |
| 网络 | `netlink` / `companion` | C6 WiFi + SNTP + mDNS / WS 服务（state/event/命令，token 鉴权） |
| 板级驱动 | `main/drv_motor·drv_encoder·drv_ina219` | TB6612（LEDC 20kHz）/ PCNT 正交 / INA219——无 PCB 外接件，TESTPANEL 实例化 |

（`display` 组件只服务 legacy TESTPANEL 的 LVGL 面板；FACE 模式的脸走 emote gfx 链，**不经 LVGL**。`esp_emote_gen_player/` 是 vendored 乐鑫官方播放器，`face` 是它的薄执行层。）

**三种启动模式**（编译期 Kconfig `NANOSOUL_MODE` 单选）：

- **FACE**（默认，产品/演示）：完整运行时——脸+HUD+视觉+soul+motion+网络+云+语音+companion。
- **SELFTEST**（首次上板/烤机）：同一套运行时 + 每 5s 一轮 19 项自检循环。
- **TESTPANEL**（legacy）：LVGL 三电机点检面板，与整机解耦。

| `voice_task` 语音会话 | voice | 0 | 5 | 事件驱动 |

| `dialog_task` | dialog | 0 | 4 | 队列(4) |
| `hud_task` | hud | 0 | 4 | 500ms |
| `push_task` WS 心跳 | companion | 0 | 3 | 1Hz |

### 2.5 云端与上位机

- **chat 双协议**（`chat.provider` 选）：Anthropic（`x-api-key` + `anthropic-version: 2023-06-01`，system 顶层字段）或 OpenAI 兼容（Bearer，system 进 messages[0]）。非流式短回复，`max_tokens` 默认 512，TLS 用内置证书 bundle，超时 20s。
- **STT/TTS**：OpenAI 兼容 `/v1/audio/transcriptions`（multipart WAV）与 `/v1/audio/speech`（收 WAV→最近邻重采样到 16kHz）。三套端点可指不同 provider，各配各的 key。
- **上位机 WS**（协议冻结 = 09）：`state` 1Hz 全量 / `event` 即时（soul_transition·face_present/lost·gazed·wake·llm_reply·fault·selftest_item）/ binary JPEG 快照；命令 `ask·set_emotion·teleop·get_snapshot·estop·clear_fault·config_reload·set_overlay·selftest`，一律回 `ack{id,ok,err}`。未知 type 必须忽略（前向兼容铁律）。

## 3. 技术配合：数据流与契约

### 3.1 本地感知→决策→输出闭环（比赛杀手锏，断网可跑）

```
OV5647 → camera(core1) —PPA 300×480→ vision(core0, ESP-DL) → tel_face_t
    → soul_task 10Hz: soul_eval()
        ├─ motion_set_intent(vx,vy,wz) → IK → duty[3] → 遥测（enabled 时才驱 TB6612）
        ├─ apply_emotion() → face_set_emotion() → emote 播放器 → 屏
        └─ telemetry_set_soul() + SOUL_TRANSITION 事件
    → hud 2Hz / companion 1Hz 从同一遥测快照对外可视化
```

决策优先级（`soul_eval`）：FAULT > 语音会话（LISTEN/THINK/SPEAK，不动）> GAZED 回避（vx=−0.5，1.5s 窗）> 无脸 IDLE（可选 idle_scan）> 有脸按 `area_ratio` 分档：>near_hi→RETREAT、<near_lo→APPROACH、之间→ENGAGE；ENGAGE 里 `frontal>0.7` 累计 ≥`gaze_hold_ms`→GAZED。所有有脸态叠加 `wz=−0.8·cx` 朝脸转向。阈值全部走 SD 配置 `behavior{}`，可现场调。

### 3.2 语音会话流水线（半双工）

能量 VAD 唤醒（或上位机 `voice_trigger`）→ `soul_notify_wake()`（LISTEN，机器人停下）→ 录音 ≤6s/尾静 800ms → THINK（脸切 think）→ STT → chat → 回复上字幕条 + `LLM_REPLY` 事件 → SPEAK → TTS → 播放（PA 拉高，期间不读麦防回授）→ 回感知闭环。

### 3.3 事件总线与遥测快照

单一事实源两条路：**连续量**走 `tel_snapshot_t` 快照（生产者 setter 写 / 消费者 `telemetry_get()` 原子读）；**离散事件**走 esp_event（`ns_event_id_t`）。事件当前唯一订阅者是 `companion`（转 WS `event` 帧）：

| 事件 | 发布者 | 含义 |
|---|---|---|
| `NS_EVT_SOUL_TRANSITION` / `NS_EVT_GAZED` | soul | 状态跳变 / 凝视触发 |
| `NS_EVT_FACE_PRESENT` / `NS_EVT_FACE_LOST` | vision | 人脸出现/消失边沿 |
| `NS_EVT_WAKE` / `NS_EVT_FAULT` | soul（voice/外部触发） | 唤醒 / 故障（含 estop） |
| `NS_EVT_LLM_REPLY` | voice / dialog | 云回复文本（≤160B） |
| `NS_EVT_SELFTEST_ITEM` | selftest | 单项自检结果 |

### 3.4 配置系统（密钥纪律）

`/sdcard/nanosoul/config.json`（模板 `sdcard_template/`，**真实密钥只在卡上、永不进仓库**），字段级 overlay 内建默认、缺卡可跑：
`wifi{ssid,password}` · `chat{provider,base_url,api_key,model,max_tokens,system_prompt}` · `stt{…}` · `tts{…,voice}` · `behavior{near_lo=0.04,near_hi=0.18,frontal_thresh=0.70,gaze_hold_ms=1500,idle_scan}` · `motion{enabled=false,max_duty_pct=40}` · `companion{enabled=true,token}` · `debug{overlay=true,log_level}`。上位机 `config_reload` 命令可热重载。

### 3.5 存储布局与资源管线

16MB flash，A/B 双 OTA（`partitions.csv`）：`ota_0/ota_1` 各 5MB · `emote_gen` 1.5MB（表情包）· `human_face_det` 1MB（人脸模型，label 名是组件硬性要求）· `srmodel` 3MB（预留 WakeNet）· `storage` FAT。
表情资产：`spiffs_image/*.bin`（5 情绪各一包，共 ~991KB）—构建时 `tools/emote_repack.py` 合成 `nanosoul_emote.bin` 随 `idf.py flash` 烧入 `emote_gen`，运行时 mmap 挂载。

### 3.6 内存纪律（bring-up 实证）

`SPIRAM_MALLOC_ALWAYSINTERNAL=4096`：≥4KB 分配走 PSRAM（emote 绘制缓冲、语音 utterance、TTS 累积均在 PSRAM），保住 256KB 内部 SRAM；esp_hosted mempool 也必须进 PSRAM（`ESP_HOSTED_MEMPOOL_PREFER_SPIRAM=y`），否则开机断言循环。PPA 输出缓冲按 cache line（128B）对齐，否则丢帧。

5. happy/blink 表情素材 + PPA 硬旋转优化（07 P3、12 I3）。

### B. 硬件落地

1. **perfboard 焊接**（图纸/接线表就绪）——把杜邦版固化，消灭接触不良。
