# 07 · 表情子系统执行计划（esp_emote_gen_player 接入）

> **状态（2026-07-05）：已执行完毕。** P0（旋转 flush 显示通路）/ P1（`tools/emote_repack.py` 合包管线）/ P2（接入 soul 状态机）已全部落地并上板实测（emote 渲染 30fps）；P3（PPA 硬旋转 + happy 表情）仍开放。落地与本文的差异：分区表以根目录 `partitions.csv`（docs/08 §3 的 16MB 版）为准，本文 §3.4 旧方案作废；Kconfig 实际为 `NANOSOUL_MODE`（FACE 默认 / SELFTEST / TESTPANEL 三选一），非 §3.2 的 `NANOSOUL_UI`；工作分支为 `soul-app`，非 §6 建议的 `face`。as-built 架构见 docs/00 §2.4。以下正文保留为执行时的计划与查证记录。

> 目标：把 `esp_emote_gen_player/`（乐鑫 espressif2022 表情引擎独立播放器）+ `spiffs_image/` 里的 5 个情绪包，接到当前无 PCB 模块版整机上，成为决策状态机的"表情执行器"。
> 屏幕动态表情复用现成件（Emote）：本组件是 Brookesia AI Expression 底下那套 gfx/emote 引擎的独立用法。

---

## 1. 现状盘点（2026-07-05，均已实际核验）

### 1.1 组件 `esp_emote_gen_player/`（仓库根，本地 vendored v0.0.2）

- 职责：挂载打包工具导出的二进制表情包 → 驱动 `esp_emote_gfx` 播放（片段规划、立即切 `anim_now` / 播完再切 `anim_fade`）。
- 依赖（component manager 拉取）：`espressif2022/esp_emote_gfx ^3.0.0`、`espressif/esp_mmap_assets`、`espressif/cjson`。IDF ≥5.0，我们的 v5.5.2 满足。
- 自带 gfx 运行时（**不是 LVGL**）：自建渲染任务 + flush 回调直连 esp_lcd 面板；另带一个顶部 tip 文本条（PuHui 20 号字体，**编进 app 约 700KB**）。
- `test_apps/` 是完整参考：P4 上 DPI 面板 `esp_lcd_panel_draw_bitmap` 做 flush、`esp_lcd_dpi_panel_register_event_callbacks(on_color_trans_done)` 回调里 `notify_flush_finished`。

### 1.2 素材 `spiffs_image/*.bin`（共 991KB）

每个 bin 都是**独立完整的 MMAP 资源包**（`esp_mmap_assets` 格式，表项 28B、文件名字段 16B），内含 `index.json` + 一个 `.eaf` 动画：

| 包 | 大小 | 帧数 | 时长@10fps | 建议语义 |
|---|---|---|---|---|
| `waiting.bin` | 93KB | 45 | 4.5s | 待机/张望 |
| `o.bin` | 123KB | 60 | 6s | 惊讶（碰撞/抬起/看到人） |
| `sleep.bin` | 159KB | 75 | 7.5s | 睡眠（暗光/久无交互） |
| `think.bin` | 300KB | 135 | 13.5s | 思考（云端对话等待） |
| `sad.bin` | 316KB | 150 | 15s | 难过（堵转急停/低电量/出错） |

EAF 实测：**画布 640×480（横向）**、24bit、JPEG 分块编码（15 块 × 640×32）。`index.json` 均为 `x:0,y:0, loop:[], fps:10`。

### 1.3 屏与固件现状

- 屏：WLK2802MIPI-15P V2（ST7701S，**原生 480 宽 × 640 高竖屏**），1-lane DSI @700Mbps，DPI 25MHz，双帧缓存在 PSRAM。`components/display/src/st7701.c` 已点亮，且已暴露 `st7701_get_panel()` + `st7701_register_color_trans_done_callback()`——正好是播放器需要的两个对接点。
- 外壳（enclosure/DESIGN.md）：史莱姆形"宽 >> 高"，前脸 facet 嵌屏当眼睛 → **屏横装**。素材按 640×480 导出与此一致。
- 当前固件（perfboard 分支）：`nanosoul_main.c` → `display_init()`（ST7701+LVGL）→ `test_app_start()`（三电机/编码器/INA219 轮转测试，LVGL 状态面板）。
- 分区表：A/B OTA（ota_0/1 各 1.5MB）+ storage FAT 640KB，**尚无表情资源分区**；flash 配置 8MB。

### 1.4 已核实的四个坑（决定方案走向）

1. **引擎无 90° 旋转**（只有水平镜像）：DPI 视频模式面板也做不了 swap_xy。640×480 素材上 480×640 竖屏，**必须在 flush 路径旋转**。
2. **`SOURCE_PATH` 不是"目录里散文件"**：`use_fs` 模式 = `fopen()` 单个完整包文件、禁用 mmap、按需 `fread`。5 个单情绪包若走文件系统方案，每次换情绪都要重新 mount（读文件 + 解析），切换有卡顿。
3. **`anim_fade` 会死锁在 gfx 回调里**：`gfx_anim_play_left_to_tail` 阻塞等渲染循环推进，凡持有渲染锁的上下文（触摸/timer 回调）调用即死锁。test_apps 的解法是队列 + 专职切换任务，必须照抄。
4. **文件名字段长度要对齐**：这批包按 16B 名字段打包，`CONFIG_MMAP_FILE_NAME_LENGTH` 必须 =16（test_apps 的预编译包用 32，别照抄它的 sdkconfig）。

## 2. 目标与非目标

**目标**

- 屏 = 机器人的脸：5 情绪可靠播放、方向正确、切换不闪不死锁。
- 表情是**纯执行器**：对上只暴露 `face_set_emotion()`，决策逻辑（何时切什么）留在自研决策状态机（soul），不混进来。
- 资产管线可重复：新增情绪 = 放素材 → 跑脚本 → `idf.py build` 出包，不靠手工摆弄二进制。
- 板外纪律不破：所有共享步骤（build、合包）板外可跑；flash/monitor 仍由持板者手动。

**非目标（本计划不做）**

- 不上整套 ESP-Brookesia 框架（后期若上，face 服务可被其 Expression 替换，接口按此预留）。
- 不做触摸交互（模块屏无触摸）。
- 不做 Rive/复杂动画、不改表情引擎内部。

## 3. 架构决策

### 3.1 新组件 `components/face`（表情执行器）

```
components/face/
├── include/face.h      # face_init / face_set_emotion(emo, FACE_NOW|FACE_FADE) / face_set_tip(text)
├── src/face.c          # player 初始化、情绪表、切换队列 + worker 任务（防死锁，坑#3）
├── src/face_flush.c    # 旋转 flush 适配：gfx 画布 640×480 → 面板 480×640
└── Kconfig             # UI 模式选择（见 3.2）
```

- `face.c` 复用 `components/display` 的 `st7701_init/get_panel/register_cb`，**不走 lvgl_port**。
- 切换语义：`FACE_NOW`（事件打断，如碰撞→惊讶）/ `FACE_FADE`（软过渡，如待机→睡眠）。worker 任务优先级 5、队列深度 8，满则丢弃并告警。
- gfx 配置基线（照 test_apps P4 参数起步）：`swap=false`、双缓冲、DMA、`buf_pixels = 640×16`、渲染任务 prio 7 / 5KB 栈 / **绑核 1**（电机控制与安全逻辑留核 0）。

### 3.2 与 LVGL 测试面板共存：Kconfig 二选一

emote gfx 与 LVGL 是两套渲染器，不同时占屏。`NANOSOUL_UI` choice：

- `NANOSOUL_UI_TESTPANEL`（默认）：现状不变——LVGL 电机测试面板，perfboard 调试不受影响。
- `NANOSOUL_UI_FACE`：表情模式——不初始化 lvgl_port，`test_app` 的关键状态（堵转告警等）走 tip 文本条。

好处：app 里 LVGL 与 emote gfx + 700KB 字体不同时链进来，1.5MB 的 ota 分区压力减半；两条路互不拖累。

### 3.3 资产：合包 + 专用分区 + mmap（否决文件系统方案）

5 个单情绪包合成**一个** MMAP 包，刷进专用 `emote_gen` 分区，`SOURCE_PARTITION + mmap_enable` 挂载：

- 切情绪 = `anim_now/fade_name`，纯 mmap 指针切换，**零 IO、无卡顿**；文件系统方案（坑 #2）每次切换要 remount，否决。
- MMAP 格式已逆向核验（头 + 28B 表项：name[16] + size + offset），且 `esp_mmap_assets` 自带官方打包脚本 `py_tool/assets_gen.py`，合包工具成本很低。

### 3.4 分区表重排（一次到位，避免二次全擦）

```
# Name,     Type, SubType,  Offset,    Size
nvs,        data, nvs,      0x9000,    0x6000
otadata,    data, ota,      0xf000,    0x2000
phy_init,   data, phy,      0x11000,   0x1000
ota_0,      app,  ota_0,    0x20000,   0x200000   # 1.5M→2M：emote gfx + 字体 ~700K 进 app
ota_1,      app,  ota_1,    0x220000,  0x200000
emote_gen,  data, spiffs,   0x420000,  0x180000   # 表情包 991K + 后续 happy 等余量
storage,    data, fat,      0x5a0000,  0xa0000
```

合计 6.25MB < 8MB，flash 配置不用动。SubType 写 spiffs 只是沿用 test_apps 惯例（mmap_assets 按 label 找分区，不管 subtype）。

### 3.5 情绪 → 状态映射（当前功能定义的落点）

| 情绪 | 触发源（无 PCB 版实际硬件） | 优先级 |
|---|---|---|
| `sad` | INA219 过流 + 编码器不动 → 堵转急停（硬需求）；MAX17048 低电量；致命错误 | **1 安全类**，`FACE_NOW`，急停期间锁定 |
| `o` | QMI8658 Tap（碰撞）/ Wake-on-Motion（抬起）中断；后续：视觉看到人 | 2 事件类，`FACE_NOW`，播完回落 |
| `think` | 云端 LLM 请求进行中 | 3 会话类，`FACE_FADE` |
| `sleep` | BH1750 暗光持续 / 长时间无交互 | 4 情境类，`FACE_FADE` |
| `waiting` | 缺省态 | 5 兜底 |

规则：高优先打断低优先；同级后到覆盖先到；事件类播完自动回落到当前情境态。**这张表由决策状态机持有，face 只吃结果**——状态机是自研核心，映射逻辑不下沉进 face 组件。

已知缺口：情绪矩阵没有正效价高唤醒（happy，"看到主人"必需），列入 P3 补素材。

## 4. 分阶段执行

### P0 — 显示通路验证（先证明"能在这块屏上正确播"）

改动最小化，先打穿最长的未知链路（旋转 flush）：

1. 分区表按 3.4 重排；`sdkconfig.defaults` 加 `CONFIG_MMAP_FILE_NAME_LENGTH=16`（坑 #4）。
2. `main/idf_component.yml` 加本地依赖 `esp_emote_gen_player: {path: ../esp_emote_gen_player}`，首次 build 联网拉 esp_emote_gfx 等，`dependencies.lock` 提交锁版本。
3. `components/face` 骨架 + **CPU 旋转 flush**：gfx 报的脏区（640 宽条带，≤640×32）逐条转置 90° 写入 `draw_bitmap` 转置坐标。旋转方向（CW/CCW）做成编译参数，上板对一次。中间缓冲 640×32×2B=40KB 内部 RAM。
   - 量级估算：15 条带 × 10fps × 20K 像素 ≈ 3M 像素/s 转置拷贝，P4 400MHz 双核无压力；P3 再上 PPA。
4. Kconfig `NANOSOUL_UI` 落地，默认 TESTPANEL；FACE 模式下 `nanosoul_main.c` 走 `face_init()`。
5. **上板（Captain 手动）**：`waiting.bin` 原样直刷分区验证：
   ```
   esptool.py write_flash 0x420000 spiffs_image/waiting.bin
   ```
   挂载走 `SOURCE_PARTITION + mmap`，`full_check` 会顺带验证名字段/校验和假设。

**验收**：板外 `idf.py build` 两种 UI 模式都过；板上 waiting 循环播放，方向正确、无错色（验证 swap=false）、无撕裂；日志确认 index 解析出 1 条目。

### P1 — 资产管线（5 包合 1 + 构建集成）

1. `tools/emote_repack.py`：
   - 解包：按已核验格式（28B 表项）拆出各包 `index.json` + `.eaf`；
   - 合并：生成总 `index.json`（name=情绪名，file/fps/loop 原样保留）；
   - 打包：调 `esp_mmap_assets` 官方 `assets_gen.py`（name_len=16）出 `nanosoul_emote.bin`；
   - 自检：合包后重新解析、逐文件字节比对 + 校验和，round-trip 不过即失败退出（板外可测）。
2. 资产真值源迁移：解出的 `.eaf` + 总 `index.json` 入库到 `assets/emote/`；`spiffs_image/` 的 5 个单包退役为原始导出存档（留 git 历史即可）。
3. CMake 挂钩：`spiffs_create_partition_assets(emote_gen ... COPY_PREBUILT_BIN nanosoul_emote.bin FLASH_IN_PROJECT)`，让 `idf.py build` 板外出包、持板者 `idf.py flash` 一次带上。
4. `face.h` API 定稿 + 5 情绪轮播 demo（定时器轮切，now/fade 交替——即 test_apps 用例去掉触摸）。

**验收**：板外 build 直接产出合包且 repack 自检过；板上 5 情绪轮播，`fade` 无死锁（长跑 ≥30min）、`now` 打断即切。

### P2 — 接入功能状态：表情成为整机反馈面

前置：P0/P1 完成；与决策状态机（自研核心，另行推进）以 3.5 的接口约定对齐。

1. 按 3.5 优先级表实现回落逻辑（face 侧只提供"播完回调/当前态查询"，仲裁在状态机侧）。
2. 现有硬件事件先接三条最有演示价值的：
   - 堵转保护触发 → `sad` + tip 显示告警（复用 test_app 的 INA219+编码器判定）；
   - QMI8658 Tap/WoM → `o`（IMU 驱动就绪后）；
   - BH1750 暗光 → `sleep`。
3. FACE 模式下 test_app 的电机测试改为 tip 文本输出关键行（保持单板调试能力）。

**验收**：断网状态下，拍一下 → 惊讶、捂住光感 → 入睡、堵转 → 难过+急停，全本地闭环（这正是比赛"断网演示"的素材）。

### P3 — 优化与补素材（非阻塞，按需排期）

1. **PPA 硬件旋转**替换 CPU 转置（`esp_driver_ppa` SRM 90°，可直写 DPI 帧缓存），实测 CPU 占用/帧率后决定是否保留 CPU 路径为回退。
2. **补 happy** 及其他情绪矩阵缺口：官方 Emote Pack.zip 素材 → Packer NEXT 按 **640×480** 导出 → repack 管线自动进包。
3. BH1750 → 屏亮度联动（需先确认模块背光控制线是否可接；当前屏不占 GPIO、背光常亮）。
4. OTA 演练：确认 app 升级不动 `emote_gen` 分区；资产版本号写进合包 index 备查。

## 5. 风险清单

| 风险 | 概率 | 缓解 |
|---|---|---|
| 旋转方向/坐标映射一次对不准 | 高（必踩） | 做成编译参数，上板半小时内可翻转重试；P0 就验 |
| app 超 2MB（gfx+字体+驱动） | 低 | 已扩到 2MB；仍超则裁 tip 字体（PuHui 700KB 可换小字库或去掉） |
| `assets_gen.py` 输出与手解格式有出入 | 低 | repack 自检 round-trip，板外即可暴露 |
| fps 语义（json 的 10fps 被解析忽略，实际节奏由引擎/EAF 定） | 中 | P0 上板目测节奏；不对则在 face 层用 segment fps 显式指定 |
| esp_emote_gfx 注册表版本漂移 | 低 | `dependencies.lock` 提交；player 本地 vendored |
| 外壳最终改竖装 | 低 | 素材重导 480×640 + 删旋转层即可，两处解耦 |

## 6. 纪律与协作约定

- **板外必过**：每步 commit 前 `idf.py build`（两种 UI 模式都编）；repack 自检进共享脚本。flash/monitor/上板验收 = Captain 手动，不进共享任务。
- **分支**：perfboard 分支上还有未提交的电机驱动改动，表情工作从 main 另开分支（建议 `face`），P0 分区表改动会导致下次烧录全擦——和 Captain 的上板窗口对齐后再合。
- **文档同步**：分区表/引脚无新增 GPIO（屏不占 GPIO），`BOARD_MAPPING.md` 不用动；本文件即表情子系统的执行真值，偏差回写这里。
