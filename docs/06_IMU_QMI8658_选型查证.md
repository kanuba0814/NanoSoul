# 06 IMU 选型查证：QMI8658(C) 顶替 ICM-42688-P

> 背景：原计划 ICM-42688-P，实际到货是 **QMI8658**（紫色 GY 模块，丝印 QMI8658A / QMI8658C，引脚 VCC/GND/SCL/SDA/XDA/XCL/ADO/INT）。本文是对它能否替代的查证记录，供大家下单/接线前对一遍。
>
> 真值源说明：引脚分配以 [`BOARD_MAPPING.md`](BOARD_MAPPING.md) 为准；规格以 **QST 官方 QMI8658C Datasheet Rev A（文档号 13-52-27，2022-06-20）** 为准。本文不复述 datasheet 全文，只摘对决策有用的部分。

## 选型结论

> **下单(JLC SMT)注意（2026-06-30）**：嘉立创 SMT 库里 **QMI8658C(`C2842151`) 已停产/邮寄**，下单改同族 **QMI8658A(`C3021082`，现货 39k、可自动贴装)**。同 LGA-14、**脚位与 4 线 SPI 接法完全一致**（A 版 datasheet 13-52-25 Table 3 + Fig.4「4-Wire SPI」核过：1=SDO 4=INT1 5=VDDIO 6/7=GND 8=VDD 12=CS 13=SCL/SPC 14=SDA/SDI，2/3/9/10/11 SPI 下可悬空）、驱动同（SensorLib/Waveshare 同支持 A/C）→ **板与固件不动，仅 BOM 料号换**。本文余下规格按 C 版写，A 版同族同适用。

**QMI8658C 可以替代 ICM-42688-P 用在 ESP32-P4 上做本项目的 IMU**。它是 6 轴、支持 SPI 与 I²C、3.3V 可直供、有 INT1/INT2 两路中断，且**片上自带 Tap / Any-Motion / Wake-on-Motion 事件引擎**，碰撞、抬起、被搬动这几个事件可直接出中断，不必全靠固件算原始数据。

- **碰撞检测** → 片上 Tap（敲击）引擎，或 Any-Motion。
- **抬起 / 被搬动** → Any-Motion / Wake-on-Motion 引擎出中断。
- **电机堵转振动辅助** → 没有专用引擎（ICM 也没有），固件读高 ODR 原始数据做能量/FFT 阈值。这条两颗芯片一样，不影响选型。

代价：噪声比 ICM-42688-P 高（陀螺约 5 倍、加速度约 2 倍），陀螺量程上限只有 ±1024 dps，6 轴最大 ODR 7.17 kHz（ICM 是 32 kHz）。**这些差距对"撞了没 / 抬了没 / 振动超阈没"这种事件判定毫无影响**——我们不做姿态积分导航，用不上 ICM 的低噪声。结合驱动生态（见下），QMI8658 在本用途上反而更省事。

> 这一条同时更新了 [`02_硬件规格_附录_驱动可用性.md`](02_硬件规格_附录_驱动可用性.md) 第 18 行对 IMU 的判断：IMU 这项从「无官方驱动、需自研」改善为「有 Espressif 官方 registry 组件 + 成熟社区库」。

### 片上事件引擎（决定能硬件判定碰撞/抬起的关键）

QMI8658C 封面自称 "Motion Co-Processor"，内含 M0+ MCU，以下引擎都能直接产生中断，配置通过 CTRL9 命令两段式写参数：

| 引擎 | DS 章节 | 对本项目用途 |
|---|---|---|
| Tap（单/双击） | §10 | 碰撞检测（撞一下 = 单击峰） |
| Any-Motion / No-Motion | §9 | 抬起 / 被搬动时姿态突变触发；放下静止触发 No-Motion |
| Significant-Motion | §9.1.3 | 持续被搬动 |
| Wake-on-Motion (WoM) | §12 | 低功耗待机被碰醒 |
| Pedometer（计步） | §11 | 本项目用不上，但说明引擎成熟 |

注意：Motion / Tap / Pedometer **只在 Non-SyncSample 模式工作**（DS §9 开头）。

## 引脚接线

[`BOARD_MAPPING.md`](BOARD_MAPPING.md) 里 IMU 走的是 **SPI（4-wire）**，与原 ICM-42688-P 的接法一致。QMI8658C 同样支持 4-wire SPI，**可直接顶替原引脚，不需要改 BOARD_MAPPING 的 GPIO 分配**。

### 方案 A：SPI（与 BOARD_MAPPING 现状一致，推荐）

| 信号 | 开发板 GPIO | 母排脚 | QMI8658 模块脚 | 备注 |
|---|---|---|---|---|
| `IMU_SCLK` | IO51 | J3-51 | SCL（= SPC，SPI 时钟） | 4-wire SPI 下 SCL 脚作 SPC |
| `IMU_MOSI` | IO50 | J3-50 | SDA（= SDI，主→从） | 4-wire SPI 下 SDA 脚作 SDI |
| `IMU_MISO` | IO49 | J3-49 | ADO（= SDO，从→主） | 4-wire SPI 下 SA0/ADO 脚作 SDO 输出 |
| `IMU_CS` | IO22 | J4-22 | （模块 CS；若模块未引出见下） | 片选，低有效 |
| `IMU_INT` | IO23 | J4-23 | INT | 中断；模块通常只引出一路（对应 INT1 或 INT2） |
| 3V3 | 开发板 3V3 脚 | — | VCC | 模块带 LDO，3.3V 直供 |
| GND | GND | — | GND | 公共地 |
| — | — | — | XDA / XCL | 辅助 I²C 主口（外挂磁力计用），本项目悬空 |

> ⚠️ **模块脚位别照搬芯片脚名**：4-wire SPI 模式下，芯片的 SCL/SDA/SA0 分别复用为 SPC/SDI/SDO（DS Table 2）。但**紫色 GY 模块的引脚是按 I²C 丝印的（SCL/SDA/ADO），不一定把芯片 CS 引出来**——很多 QMI8658 模块只引 8 脚、默认接成 I²C。**下单/接线前必须实物确认这块模块到底有没有 CS 脚、能不能进 SPI 模式**（见"人工复核"节）。如果模块焊死成 I²C，就走方案 B。

### 方案 B：I²C（模块只支持 I²C 时的回退）

模块默认 I²C 接法：SCL→IMU_SCLK 脚改作 I²C SCL、SDA→I²C SDA、ADO→地址选择、INT→IMU_INT。但 **BOARD_MAPPING 当前没有给 IMU 留 I²C 走线**（左排 I²C0 IO7/8 是板载 ES8311 共用、不可碰；I²C1 IO20/21 在右排给了 BH1750）。

若必须走 I²C，两条路：
1. 把 QMI8658 挂到 **I²C1（IO20/21）与 BH1750 共总线** —— 地址不冲突（QMI 0x6A/0x6B，BH1750 0x23/0x5C），电气可行，但要改 BOARD_MAPPING 和 PCB 走线。
2. 维持独立总线则要新分配两个 GPIO 做 I²C —— 改动更大。

**任选都需先改 BOARD_MAPPING 真值源再动电路**，不在本文擅自决定。

## 驱动选择

QMI8658 在 ESP 生态有三套可用驱动，按推荐度排：

| 驱动 | 来源 | 接口 | 覆盖 | 取舍 |
|---|---|---|---|---|
| **lewisxhe/SensorLib** | GitHub 225★ / registry `lewisxhe/sensorlib` | I²C + SPI | 最全：BasicRead / FIFO / **Pedometer / Tap / WakeOnMotion** / SyncMode 等 | 要用事件引擎就上它；最活跃、例程最多 |
| **waveshare/qmi8658** | ESP 官方 Component Registry | I²C | 量程/ODR/原始数据/温度/时间戳，**未暴露事件引擎** | 只读原始数据时最省事，`idf.py add-dependency "waveshare/qmi8658^2.0.0"` |
| **esp-idf-lib/qmi8658c** | GitHub / registry，BSD-3 | I²C | 基础读取为主 | 备选，社区小 |

- **要硬件 Tap / WoM 中断（碰撞/抬起）→ 选 SensorLib**（含对应例程，且支持 SPI）。
- **只读原始数据自己算 → Waveshare 官方组件最简单**。
- 对比 ICM-42688-P：ICM 没有 Espressif 官方 registry 组件，主流是自己拉 InvenSense C 驱动移植。**驱动生态上 QMI8658 反而更顺手。**

## 备用方案

按"真买得到模块 + ESP-IDF 驱动现成"排序：

1. **LSM6DSO / LSM6DSOX（ST）— 首选备用。** 6 轴、I²C+SPI、3.3V，片上 FSM/MLC + Tap/WoM/free-fall 引擎，噪声介于 QMI 与 ICM 之间。ST 官方 C 驱动 + 社区驱动易移植，淘宝 GY 模块常见、LCSC 有货。货源稳、不踩假货坑。
2. **正品 ICM-42688-P 模块 — 性能天花板。** APEX 引擎齐全、噪声最低。代价：淘宝改标/假货多，认正品；驱动要自己移植 InvenSense。性能要顶配才选。
3. **MPU6050 — 仅临时验证。** 最便宜、驱动遍地，但已停产、噪声温漂差、无现代事件引擎。不进正式 BOM。
4. **BMI270（Bosch）— 不推荐做省事备用。** 初始化要加载固件 blob、配置最繁琐，ESP-IDF 现成驱动不如前几个顺。

## 下单 / 接线前必须人工复核（红线项，别赌）

1. **模块到底支不支持 SPI / 有没有 CS 脚。** 紫色 GY 模块多按 I²C 8 脚出，**很多没把芯片 CS 引出来**。先看实物丝印/原理图：有 CS → 走方案 A（与 BOARD_MAPPING 一致）；没有 CS → 只能 I²C，走方案 B 并改真值源。**这条不确认就别下结论接线。**

2. **I²C 地址冲突。** QMI8658 地址由 ADO/SA0 决定：高=0x6A、低=0x6B（DS §16.3.1）。若走方案 B 与 BH1750（0x23/0x5C）共 I²C1，地址不冲突；但要确认模块上 ADO 默认上/下拉到哪一边，别两颗 IMU 或别的从机撞地址。

3. **3.3V vs 1.8V。** datasheet 推荐 VDD/VDDIO 1.71–3.6 V，**典型工作点是 1.8 V**，电气表里的电流/性能都在 1.8V 测。**模块**带 LDO+电平（VCC 标 3.3–5V），吃开发板 3V3 没问题；但如果将来要上**裸芯片**进 PCB，得自己确认 1.8V 供电与电平匹配，别直接照模块经验。本版用模块 → 3.3V 直供 OK。

4. **INT 路由。** QMI8658 有 INT1+INT2，每个事件可软件选走哪路（CTRL8.bit6）。模块通常**只引出一路 INT**——要确认它内部接的是 INT1 还是 INT2，固件里把目标事件路由到那一路，否则中断永远不来。BOARD_MAPPING 的 `IMU_INT`(IO23) 接模块这一路即可。

5. **ODR > 1 kHz 噪声。** datasheet（Table 12 note 11）明确：陀螺 ODR 设到 1 kHz 以上时噪声显著上升，不建议对噪声敏感的应用拉到 >1 kHz。我们做事件/振动阈值，**别盲目把 ODR 拉满**；按需求设（碰撞/抬起几百 Hz 足够，振动判定按目标频段定，留足裕量即可）。
