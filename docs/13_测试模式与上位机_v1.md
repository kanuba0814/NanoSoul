# 13 · 测试模式与测试上位机 v1

> 目的：在**真机**上系统化测试所有硬件/传感器的信息范围，并能从上位机**覆盖/注入**传感数值去驱动核心代码（soul 状态机、堵转保护、事件反应），实时观察机器人反应。
>
> 本文是**测试扩展协议的真值源**。它对 [`09_上位机接口协议_v1.md`](09_上位机接口协议_v1.md) 做**加法演进**（新 `type` 旧端忽略、字段只增不改语义——docs/09 前向兼容铁律）。固件实现见 `components/testlink/`、`components/simsense/`、`main/app_testmode.c`；上位机见 `tools/testhost/index.html`。
>
> 不做 PC 端设备模拟器——测试对象就是接好的真机。

## 1. 进入测试模式

- **硬件跳线**：上电时把 **IO48 短接到 GND** → 进 TEST 模式（内部上拉，采样去抖后释放该脚；开路 = 正常 FACE）。IO48 在开发板右排边沿最后一脚。冲突时 fallback = IO33（改 `main/nanosoul_main.c` 的 `TEST_STRAP_GPIO` 一处）。
- **板外无跳线**：`idf.py menuconfig` → NanoSoul → Boot mode → **Test mode**（`CONFIG_NANOSOUL_MODE_TEST`）强制进入，供无实物构建/联调。
- strap **优先于** Kconfig。

TEST 模式 = 完整 FACE 运行时（soul 照常跑、companion WS 起、所有传感器在线）+ 测试服务：传感覆盖注入、`motor_test`、USB-Serial-JTAG NDJSON 通道、强制连接信息 HUD、屏幕**长按 = 急停**。

**关键设计**：覆盖值在各传感生产者边界注入，走**正常全链路**（真实检测器 → 事件总线 → soul → telemetry → 表情/电机）。测的是真核心代码对刺激的真实反应，不是旁路仿真。

## 2. 连接上位机

打开 `tools/testhost/index.html`（纯浏览器单页，零安装零 CDN），两种通道任选：

- **WebSocket**：`ws://nanosoul.local/ws?token=<companion.token>`（或填 IP）。开发板联网后 HUD 屏上会显示 IP。连接建立即收到一帧 `hwinfo`。
- **WebSerial**（**仅 Chromium 系** Chrome/Edge）：USB-Serial-JTAG，115200，NDJSON（一行一 JSON）。**Wi-Fi 不通也能测**。上位机按行首 `{` 区分协议与日志，非 JSON 行进日志窗。

> 串口占用说明：TEST 模式把 USB-Serial-JTAG 用作协议通道，故固件 `CONFIG_ESP_CONSOLE_SECONDARY_NONE`——**日志改走 UART0**。持板者若习惯经 USJ 看 log 会受影响；flash 走下载模式不受影响。

## 3. 协议加法（机器人 → 上位机）

信封同 docs/09：`{"v":1,"type":"<kind>","ts":<开机ms>,...}`。

### `hwinfo`（连接时推 + 响应 `hwinfo_get`）
```json
{"v":1,"type":"hwinfo","ts":123,
 "fw":{"ver":"...","idf":"v5.5.2","mode":"TEST"},
 "i2c1":{"pins":"SDA=20,SCL=21","scan":[35,64,106],
   "expect":[{"addr":106,"name":"QMI8658","present":true,"note":"..."},
             {"addr":35,"name":"BH1750","present":true},
             {"addr":64,"name":"INA219","present":true},
             {"addr":54,"name":"MAX17048","present":true,"note":"固件未接入"}]},
 "i2c0":{"pins":"SDA=7,SCL=8","scan":[24,54,56]},
 "pins":{"motors":[{"m":0,"pwm":2,"in1":3,"in2":4,"enc_a":30,"enc_b":31,"stby":51},...],
   "imu_int":23,"strap_test":48},
 "range":{"lux":[1,65535],"accel_g":4,"current_a_fs":3.2,
   "enc_cpr_motor":28,"gear":118,"duty_max":1023,"stall_ma":400}}
```
`present` 由现场 I²C 探测决定（`scan` 为 0x08–0x77 全扫结果）。

### `sense`（默认关，`sense_rate` 开，10–50Hz；snprintf 组帧）
```json
{"v":1,"type":"sense","ts":123,"seq":42,
 "accel":[0.02,-0.01,9.81],"gyro":null,"lux":312.5,"cur_ma":85,
 "enc":[[1234,55.2],[..],[..]],"duty":[0,-102,102],
 "lifted":false,"tilted":false,"ovr":5}
```
`enc[i]` = `[计数, 电机轴 rpm]`；`ovr` = 覆盖激活位图（bit i = 通道 i，见 §5）。`gyro` 当前恒 `null`（驱动只读 accel）。

### `event` 增补
docs/09 事件表之外，补 `selftest_item`：`{"name","result":0|1|2,"detail","round"}`（0=PASS/1=FAIL/2=SKIP）。触发 `selftest` 命令后逐项流出。

## 4. 协议加法（上位机 → 机器人命令）

每条 `{"v":1,"type":"<cmd>","id":<n>,...}`，回 `{"type":"ack","id":<n>,"ok":..,"err":".."}`。

| cmd | 字段 | 动作 |
|---|---|---|
| `hwinfo_get` | `{mode?}` | 回一帧 `hwinfo` |
| `sense_rate` | `{hz:0..50}` | 开/调/关 sense 流；ack 回显 `hz` |
| `override_set` | `{ch, v, ttl_ms}` | 覆盖某通道；`v` 标量或数组（长度须匹配，见 §5）；`ttl_ms=0` 常驻 |
| `override_clear` | `{ch \| "*"}` | 清一个通道或全清 |
| `inject_event` | `{name, text?}` | 直接 post 一个交互事件（见 §6） |
| `motor_test` | `{m:0..2, duty:±1023, ms:100..5000}` | 单电机开环跑一段（到时 coast）；**仅 TEST 模式**、FAULT 态拒绝、参数夹限；执行期摘 motion apply 回调防抢 |
| `motor_stop` | `{}` | 全停 + 拉低 STBY |

沿用 docs/09 既有命令（`ask/set_emotion/teleop/get_snapshot/estop/clear_fault/config_reload/set_overlay/selftest/pc_state`）不变；`selftest` 现真跑一轮（结果走 `selftest_item` 事件流）；`get_snapshot` 仅 WS 通道（串口回 `err:"ws only"`）。

## 5. override 通道（`components/simsense/`）

| ch 名 | 值数 | 含义 | 插桩点 |
|---|---|---|---|
| `lux` | 1 | lx | `light.c` 1Hz → 真实迟滞 → DARK/BRIGHT |
| `accel` | 3 | m/s² (x,y,z) | `imu.c` 100Hz → 真实 tap/lift/tilt 检测器 |
| `gyro` | 3 | dps（预留，当前不消费） | — |
| `current_a` | 1 | A（正=放电） | `app_sense.c` 10Hz；覆盖时强制 `current_present=true` 让堵转判定吃到 |
| `enc_rpm` | 3 | 电机轴 rpm | `app_sense.c` 10Hz（count 不覆盖） |
| `face` | 5 | present,cx,cy,area,frontal | `vision.cpp` `vision_get()`（soul 唯一视觉入口，无摄像头也生效） |

## 6. inject_event 名字表

`tap` / `tap2`(双击) · `lifted` / `placed` · `dark` / `bright` · `touch` / `touch_long` · `loud` · `wheel_moved` · `wake` · `face_present` / `face_lost` / `gazed` · `stall`(带 `text`) / `fault`(带 `text`)。

## 7. 硬件真值表（无 PCB 模块版；与 hwinfo 帧同源）

| 项 | 真值 |
|---|---|
| I²C1 (SDA=IO20/SCL=IO21, 100kHz) | QMI8658 **0x6A**(备 0x6B, INT=IO23, WHO_AM_I 寄存器 0x00=0x05, ±4g=8192LSB/g) · BH1750 **0x23**(1–65535lx) · INA219 **0x40**(0.1Ω shunt, LSB 10µV, ±3.2A) · MAX17048 **0x36**(在线但固件未接入) |
| I²C0 板载 (IO7/8) | ES8311 **0x18** · FT6x36 触摸 **0x38** · OV5647 SCCB **0x36**(不同总线,不冲突) |
| 电机(LEDC 20kHz, duty≤1023) | M0 PWM=IO2/IN1=IO3/IN2=IO4 · M1 IO5/IO24/IO25 · M2 IO26/IO27/IO32；**STBY 分置 IO51(M0/M1)+IO52(M2)**，同拉同放，低=急停 |
| 编码器(开漏,上拉 3V3) | M0 IO30/IO31 · M1 IO28/IO29 · M2 IO46/IO47；**电机轴 28 计数/圈**(输出轴=×118=3304,仅换算) |
| 堵转判定 | 电流 ≥ `protect.stall_ma`(默认参考 400mA) 且某轮 |duty|>307 且 |rpm|<5 持续 `stall_ms` |
| 测试 strap | **IO48 短接 GND**（fallback IO33） |

## 8. 验证清单

**板外（队友可跑）**：
- `idf.py build` 全绿（FACE 默认 + `CONFIG_NANOSOUL_MODE_TEST` 各一次）。
- SELFTEST 构建下纯逻辑 sim + `override_sim` 全绿。
- 浏览器直接打开 `index.html` 无 console 报错（headless chromium 注入合成帧回归通过）。

**板上（持板者，一次过）**：
1. 跳线 IO48→GND 上电 → HUD 显 TEST + IP；开路 → 正常 FACE。
2. 浏览器连 WS → hwinfo：0x6A/0x23/0x40 全绿（0x36 出现属正常）。
3. 量程实测并导出报告：遮光 <5lx / 手电 >1000lx；翻板六面 accel 各轴 ±9.8；`motor_test` 三轮正反转 rpm 符号正确、空载电流 ~40mA/轮；手拨轮 count 变化。
4. 堵转两法：真堵（手捏轮 + teleop）→ `stall` 事件 + 电机断电；纯注入场景（`current_a=0.6` + `enc_rpm=0` + teleop）→ 同样跳闸——证明保护对**数值**而非物理敏感。
5. 反应链：覆盖 `lux=0` → soul 进 DOZE；`accel` 敲击波形 → 表情反应；inject `lifted` → LIFTED 冻结电机；覆盖 `face` → 离开 IDLE。
6. 拔 Wi-Fi 配置重启 → WebSerial 走通上述 2/3/5。
7. UART0 日志无异常；FACE 模式回归（老命令/表情/自主行为）不受影响。

## 9. 边界

- WebSerial 仅 Chromium 系；其余浏览器走 WS。
- `motor_test` 安全：仅 TEST 模式 + FAULT 拒绝 + 参数夹限 + 执行期摘 motion apply；屏幕长按 ESTOP / `motor_stop` / STBY 拉低多重兜底。
- sense 50Hz×~250B≈12KB/s，WS/USJ 均宽裕。
- token 明文 query 沿用 docs/09（LAN only），测试页不改安全模型。
