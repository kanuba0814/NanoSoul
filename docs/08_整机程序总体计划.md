# NanoSoul 整机程序总体计划（v1，给执行者）

> 执行前必读：本计划的每一条"已核实事实"都是本轮实际查证/实测过的，**不要凭训练记忆推翻**。参考实现在 `/home/gxxl/testP4/`（同一块板上大多验证通过）和本仓库 `esp_emote_gen_player/test_apps/`。表情子系统已有独立计划 `docs/07_表情子系统_执行计划.md`（本计划的 Phase A 就是它，细节以它为准）。

## 0. Context

NanoSoul = ESP32-P4 桌面陪伴机器人（嵌赛/乐鑫赛道）。当前仓库固件只有：ST7701 屏 + LVGL 电机测试面板 + 三电机/编码器/INA219 驱动（perfboard 分支，未提交的三电机化改动）。本计划把它扩成**完整整机程序**：

- 本地人脸检测（ESP-WHO/esp-dl，断网本地感知）
- 决策闭环：距离带靠近/退后 + 近距正脸持续→"被注视"→退后；行为触发表情变化
- 表情脸（emote 引擎，docs/07）+ **debug 版本默认在屏上叠加硬件参数**（电机输出、编码器、电流、帧率、状态机状态等）
- SD 卡存用户配置（WiFi、LLM 端点/key、行为阈值、运动开关）
- 云端 LLM：OpenAI 兼容 + Anthropic 兼容双协议，配置全在 SD 卡
- **语音链路**（用户已拍板直接上）：ESP-SR 唤醒 → 录音 → STT → LLM → TTS → 扬声器
- **上位机接口（遥测+控制）**：冻结 WebSocket JSON 协议 v1 + 固件侧实现；PC 端程序为后续独立工程

用户拍板的三个决策：① 语音链路本计划就做；② 运动按低速设计，**当前电机不接线**，但计算出的输出参数必须显示在 debug 叠加层；③ 上位机 = 遥测+控制双向。

硬件就绪状态：**相机、屏幕、SD、C6 WiFi、音频 = 板载就绪**；电机/编码器/INA219/IMU/BH1750 = 暂不接（驱动保留，探测缺席降级）。

## 1. 已核实事实（执行时直接引用，勿再查证）

### 1.1 板卡（Waveshare ESP32-P4-WIFI6，实测来源 testP4/board_pins.h + docs/BOARD_MAPPING.md）

| 资源 | 事实 |
|---|---|
| Flash / PSRAM | 板载 16MB flash（当前 sdkconfig 只配了 8MB，本计划改 16MB）；32MB PSRAM（200MHz HEX 已配好） |
| TF 卡 | 固定引脚 CLK=43 CMD=44 D0=39 D1=40 D2=41 D3=42，板载 10k 上拉；**testP4 实测用 SDSPI 模式挂载成功**（CMD=MOSI、D0=MISO、D3=CS，`sd_pwr_ctrl_new_on_chip_ldo` LDO_VO4 供电必须开）。照抄 `testP4/main/sd_storage.c` |
| 板载 I2C0 | GPIO7/8（SDA=7 SCL=8），挂 ES8311(0x18?)、触摸 FT6x36(0x38)、**相机 SCCB OV5647(0x36)**。NanoSoul 现有代码没碰它，需要新建 board_i2c0 模块 |
| 音频 | ES8311 + NS4150B 功放；I2S0：MCLK=13 BCLK=12 WS=10 DOUT=9 DIN=11(录音)，PA_EN=GPIO53 高有效。播放路径 testP4 已验证（`audio_player.c`），**录音路径未验证 = 风险项** |
| 相机 | OV5647 MIPI-CSI；CSI 与 DSI **共用 MIPI DPHY 轨 LDO_VO3 @2500mV**。esp_video 默认 CSI LDO 单元不对，**必须打 cmake 补丁**（照抄 `testP4/cmake/patch_esp_video_ldo.cmake`，改 `CSI_LDO_UNIT_ID=3`、`CSI_LDO_CFG_VOL_MV=2500`） |
| 屏 | WLK2802 ST7701S 2.8" **480 宽×640 高竖屏**，1-lane DSI @700Mbps，DPI 25MHz；已在 `components/display/` 点亮，`st7701.h` 暴露 `st7701_get_panel()` + `st7701_register_color_trans_done_callback()` |
| C6 WiFi | 经 SDIO + esp_hosted，**C6 固件板载预刷**；host 侧组件 `espressif/esp_wifi_remote ^1.5.1` + `espressif/esp_hosted ^2.12.6`（testP4 实测版本，扫描/连接/ping 通过，照抄 `app_wifi.c`） |
| USB | GPIO24/25 = USB D-/D+（USB-Serial-JTAG）。**当前无 PCB 电机映射 M1 IN1/IN2 = IO24/25 与之冲突**——电机一使能串口日志断。本阶段电机不接线所以不触发；接线阶段前须挪 M1 引脚或接受丢串口 |

### 1.4 云端 API 形态（已核对 claude-api 参考）

- **Anthropic 兼容**：`POST {base_url}/v1/messages`，头 `x-api-key: <key>`、`anthropic-version: 2023-06-01`、`content-type: application/json`；体 `{model, max_tokens, system, messages:[{role:"user",content:"..."}]}`；回复取 `content[]` 中 `type=="text"` 块；`stop_reason=="refusal"` 需处理（显示 sad/致歉文案）。多轮=客户端自持历史。默认 model 示例 `claude-opus-4-8`。
- **OpenAI 兼容**：`POST {base_url}/v1/chat/completions`，头 `Authorization: Bearer <key>`；体 `{model, messages:[{role:"system"},{role:"user"},...]}`；回复取 `choices[0].message.content`。
- **STT/TTS 走 OpenAI 兼容音频端点**（Anthropic 无语音）：STT=`POST {base}/v1/audio/transcriptions`（multipart WAV，字段 model/file）；TTS=`POST {base}/v1/audio/speech`（`response_format:"wav"` 便于直接播放）。STT/TTS 端点允许与 chat 用不同 provider（SD 配置分开三段）。
- 全部走 `esp_http_client` + esp-tls，`CONFIG_MBEDTLS_CERTIFICATE_BUNDLE=y`。非流式起步（max_tokens ≤512，桌面机器人短回复）。

### 1.5 已知坑（每条都有实证，实现时直接规避）

1. **esp_video CSI LDO**：不打补丁相机必挂（testP4 commit "Fix camera CSI DPHY LDO rail"）。
2. **CSI 偶发崩溃**：开 `CONFIG_CAM_CTLR_MIPI_CSI_ISR_CACHE_SAFE=y`（docs/02 附录）。
3. **emote 包名字段 16B**：`CONFIG_MMAP_FILE_NAME_LENGTH=16`（docs/07 坑#4）。
4. **emote `anim_fade` 在 gfx 回调里死锁**：切表情必须走队列+专职任务（docs/07 坑#3）。
5. **表情素材 640×480 横 vs 屏 480×640 竖**：flush 路径旋转 90°（P0 CPU 转置，后续 PPA），docs/07 已定方案。
6. **SD 用 SDSPI 不用 4-bit SDMMC**：testP4 的选择（实测可挂载）；配置文件读写吞吐足够。必须先 `sd_pwr_ctrl_new_on_chip_ldo(chan 4)`。
7. **人脸检测模型分区名固定 `human_face_det`**（组件按 label 找）。
8. **esp-dl 是 C++**：vision 组件用 .cpp 实现 + `extern "C"` C 门面，其余组件保持 C。
9. **两套渲染器不并存**：FACE 模式（emote gfx + HUD 标签）与 TESTPANEL 模式（LVGL 电机面板）Kconfig 二选一，默认 FACE。
10. **IO24/25 = USB 串口**：电机 M1 使能即断串口日志（本阶段不接线不触发，接线前解决）。
11. 相机 SCCB 挂在板载 I2C0(7/8)，与外设 I2C1(20/21) 是两条总线，别混。
12. PPA（`driver/ppa.h`）P4 硬件缩放/旋转可用（testP4 相机 240×240 预览实测）；HW JPEG（`driver/jpeg_encode.h`）可用（拍照存 SD 实测）。

```

  voice/                 ES8311 录/放（esp_codec_dev）+ ESP-SR AFE/WakeNet + 对话流程编排
```

### 2.1 自动循环自检（selftest，贯穿所有阶段的验收载体）

目的：**Captain 只做两件事——刷固件、回贴串口日志**；剩下的验证与重试由自检循环和执行者自主完成，不需要用户逐步指挥。

- 框架：`selftest_register(name, fn, flags)`；检查函数返回 `{PASS|FAIL|SKIP(硬件缺席), detail[64]}`。启动模式三选一（Kconfig `NANOSOUL_MODE`：`FACE`(默认) / `SELFTEST` / `TESTPANEL`），SELFTEST 也可由 WS 命令 `selftest {}` 或串口命令随时触发单轮。
- 运行方式：上电自动跑全部检查项 → 屏上显示 PASS/FAIL 矩阵 → **进入循环烤机**（每轮间隔 5s，长跑统计累计失败次数/掉线次数）。串口每项输出一行机器可读 JSON：`{"st":"selftest","item":"sd_mount","pass":true,"detail":"16GB FAT","round":3}` —— 执行者直接 grep 日志定位问题、改码、再出固件，**自主迭代到全绿，不逐步请示**。
- 检查项随阶段累积注册：
  - Phase 0：`sd_mount`、`config_parse`、`psram`、`partition_layout`
  - Phase A：`emote_mount`（合包 index 条目数）、`emote_cycle`（5 情绪各切一遍，渲染帧计数增长）、`hud_draw`
  - Phase B：`i2c0_probe`（SCCB 0x36 应答）、`camera_stream`（1s 内出帧数≥5）、`face_detect_bench`（合成/静态帧推理耗时）、真人项标记 MANUAL
  - Phase C：`motion_ik`（给定 (vx,vy,wz) 断言三轮 duty 数值，纯计算可全自动）、`soul_sim`（注入伪 face_obs 序列断言状态迁移 IDLE→APPROACH→ENGAGE→GAZED）
  - Phase D：`wifi_connect`、`sntp`、`llm_ping`（两 provider 各发一条 "ping" 问答，校验非空回复；无 key 则 SKIP）
  - Phase E：`codec_playback`（1kHz 音 1s）、`mic_record`（录 2s 写 SD + RMS 能量阈值判有声）、`wakenet_load`；唤醒实测标 MANUAL
  - Phase F：`ws_loopback`（本机起客户端 ping /ws 收 state 帧）
- `soul_sim`/`motion_ik` 这类纯逻辑项**同时编成板外可跑的宿主单测思路**（不依赖真机的断言放进检查函数，板外至少保证编译期与逻辑评审），真机项 SKIP 降级不算失败。

**任务/核分配（起步值，上板再调）**：core1 = gfx 渲染(prio7) + 相机取流(5)；core0 = 人脸检测(4) + soul 决策(5, 10Hz) + motion 定时器(6, 50ms) + voice/AFE(5) + netlink/llm(3)。检测器输入用 PPA 缩到 ~320×240 RGB565 再喂 `HumanFaceDetect`。

**数据流**：vision → (queue) → soul → {motion 意图, face 表情, tip 文案, telemetry 事件}；voice 唤醒 → soul 进入 LISTEN/THINK/SPEAK 状态；WS 命令 → soul（ask/estop/emotion override）。云端 LLM 永不进感知决策回路（宪法红线）。

**soul 状态机 v1**（阈值全部来自 SD 配置，默认值写进 config 缺省）：

| 状态 | 进入条件 | 表情 | 运动意图 |
|---|---|---|---|
| IDLE | 缺省/无人脸 | waiting | 停（可选慢速扫视，默认关） |
| ENGAGE | 有人脸且 area∈[near_lo,near_hi] | waiting | 转向对中（wz∝cx偏差） |
| APPROACH | 有人脸且 area<near_lo | waiting | 前进+对中，vx=slow |
| RETREAT | area>near_hi | o | 后退 vx=-slow |
| GAZED | ENGAGE 中 frontal_score>阈值 持续 gaze_hold_ms | o（害羞） | 后退一小段后回 ENGAGE |
| LISTEN/THINK/SPEAK | 唤醒/等 LLM/播 TTS | waiting/think/waiting | 停 |
| FAULT | 堵转(有 duty 编码器不动)/致命错误 | sad | 急停(STBY 拉低)+锁定 |

优先级：FAULT > 语音会话 > GAZED/RETREAT > APPROACH/ENGAGE > IDLE。frontal_score 用检测关键点（双眼-鼻对称度 + 双眼距/框宽）；距离代理 = bbox 面积比。

### Phase A — 表情脸 + debug HUD（执行 docs/07 的 P0+P1，加 HUD）
1. 按 docs/07 落地 `components/face`（旋转 flush、合包管线 tools/emote_repack.py、emote_gen 分区、切换队列）。
2. `components/hud`：在 gfx 画布上建 6-10 行 `gfx_label`（画布坐标系 640×480），2Hz 从 telemetry 刷新：`SOUL:<state> FACE:<x,y,area,frontal> MOT:<vx,vy,wz|d0,d1,d2> ENC:<rpm×3> CUR:<mA|-- > NET:<ip|off> LLM:<idle|think> VOI:<idle|listen|speak> FPS:<render/detect> HEAP:<free>`。`debug.overlay` 可关。
   **上板验收**：5 情绪轮播正常 + HUD 数字实时跳动（此时电机/编码器显示 0/absent 属正常）。

### Phase B — 相机 + 本地人脸检测
1. `board_i2c0` 模块（GPIO7/8 master bus，给相机 SCCB；触摸/编解码器共用留接口）。
2. 移植 testP4 `camera.c`（esp_video V4L2 + mmap 双缓冲 + PPA 缩放）+ **cmake LDO 补丁**进本仓库。
3. `components/vision`：依赖 `espressif/human_face_detect ^0.5.0`；检测任务循环取帧→`HumanFaceDetect::run()`→算 area_ratio/cx/frontal_score→发队列+telemetry；模型烧 `human_face_det` 分区。
4. HUD 显示 bbox 数据与检测 FPS。（可选加分项：GAZED 时 HW JPEG 拍快照存 SD——testP4 已有 `camera_capture_jpeg`。）
   **上板验收**：断网状态下，人进画面 HUD 出现 face 数据，正脸/侧脸 frontal_score 有区分度，检测 ≥5 FPS。

### Phase C — 决策闭环 + 运动输出（不接轮）
1. `components/motion`：三轮全向 IK（120° 布局，轮向量投影，输出三轮目标转速→duty），门控 `motion.enabled`（默认 false：只算不驱动，全量进 telemetry/HUD）；堵转守护（有 duty 且编码器静止 800ms → FAULT）与丢脸即停留作接线后启用。
2. `components/soul`：按 §2 状态机实现；行为触发表情（经 face 队列）；所有状态迁移打 telemetry 事件。
   **上板验收**：人由远及近，HUD 依次显示 APPROACH→ENGAGE→RETREAT 的运动意图数值；盯着看 1.5s 触发 GAZED + 表情变 o；全程断网。

### Phase D — 联网 + LLM 文字链路
1. `components/netlink`：esp_wifi_remote+esp_hosted 依赖；移植 testP4 `app_wifi.c`（STA 连接，凭据来自 SD config）；SNTP、mDNS。
2. `components/llm`：双协议 chat（§1.4 形态），TLS 证书 bundle；请求期间 soul 进 THINK（表情 think）；回复上屏（face tip 文案）；`stop_reason=="refusal"`/HTTP 错误→sad+短提示。串口控制台命令 `ask <text>` 做首个触发器。
   **上板验收**：SD 卡改 provider 分别用 OpenAI 兼容与 Anthropic 兼容端点各问答一次成功；拔网线→请求超时→本地闭环不受影响（表情/检测/决策照跑）。

### Phase E — 语音链路
1. `components/voice`：esp_codec_dev 起 ES8311 全双工 I2S（录 16k/16bit 单声道，DIN=11；放 = testP4 audio_player 路径，PA=53）；**录音路径首次验证，列为本阶段第一个上板项**（先写 raw PCM 到 SD 人耳验听）。
2. 接 ESP-SR：AFE(含 AEC 可后开) + WakeNet9（唤醒词 `wn9_nihaomiaoban_tts2`，模型进 `srmodel` 分区，走 esp-sr 官方 CMake 烧录流程）。
3. 会话编排：唤醒→LISTEN（VAD 截段，≤8s）→STT→chat→TTS(wav)→播放（半双工：播时闭麦）；全程 soul 状态/表情联动；HUD 显示 VOI 状态。
   **上板验收**：喊唤醒词→说一句→机器人语音回答；期间表情 waiting→think→waiting；断网时唤醒后播本地兜底提示音/文案。

### Phase F — 上位机接口（协议冻结 + 固件侧）
1. 协议文档 `docs/09_上位机接口协议_v1.md`（§6 全文照搬冻结）。
2. `components/netlink` 内加 `esp_http_server` + WebSocket `/ws`：连接鉴权（config 的 companion.token，query 参数携带）；遥测推送（telemetry 事件→JSON，状态全量 1Hz + 事件即时）；命令处理（§6 列表）路由到 soul/face/motion/llm。
3. 快照命令：HW JPEG 编码当前帧，WS 二进制帧回传。
   **上板验收**：PC 上用 `websocat`/浏览器控制台连上 `ws://nanosoul.local/ws?token=...`，能看到状态流；发 `ask` 收到 LLM 回复事件；发 `estop` 后 soul 进 FAULT。

> PC 端配套程序（可视化陪伴面板、用户状态长期分析）= 后续独立工程，不在本仓库，本计划只交付协议与固件端点。

## 6. 上位机 WebSocket 协议 v1（冻结稿）

- 传输：`ws://nanosoul.local/ws?token=<companion.token>`，LAN only；文本帧 = UTF-8 JSON，二进制帧 = JPEG 快照。
- 通用信封：`{"v":1, "type":"<kind>", "ts":<ms since boot>, ...}`；未知 type 必须忽略（前向兼容）。
- 机器人→PC：
  - `state`（1Hz 全量）：`{soul, emotion, face:{present,cx,cy,area,frontal}, motion:{intent:[vx,vy,wz], duty:[d0,d1,d2], enabled}, enc_rpm:[..], current_ma|null, net:{ip,rssi}, llm:"idle|busy", voice:"idle|listen|think|speak", heap, fps:{render,detect}}`
  - `event`（即时）：`{name:"soul_transition|gazed|wake|llm_reply|fault|...", data:{...}}`；其中 `llm_reply.data={text}`——用户状态类事件（在席/离席、被注视时长、互动次数）都从这里出，供 PC 端做陪伴分析。
  - `snapshot`（二进制 JPEG，响应 get_snapshot）
- PC→机器人（命令，均回 `{"type":"ack","id":...,"ok":bool,"err":...}`）：
  - `ask {text}` 文字问答（复用 llm 链路，回复走 llm_reply 事件）
  - `set_emotion {name, mode:"now|fade"}` 表情覆盖（10s 后回归状态机）
  - `teleop {vx,vy,wz,ttl_ms}` 遥控运动（仅 motion.enabled 时生效，ttl 到期自动停）
  - `get_snapshot {}`、`estop {}`、`config_reload {}`、`set_overlay {on}`

## 7. 风险清单（按杀伤力排序）

| 风险 | 缓解 |
|---|---|
| ES8311 录音路径从未验证（板载麦→AFE 增益/时钟） | Phase E 第一步单测录 PCM 到 SD；不行则回退 UAC/外接麦排查；语音整段可降级为文字通道（Phase D 已可用） |
| app 超 3.1MB（gfx+esp-dl+esp-sr+hosted+TLS 同仓） | 分区留了余量；仍超则裁 tip 字体(700KB)/esp-sr AFE 精简/压 ota 到 2.75M×2 |
| 检测帧率不足或误检多 | 输入降到 240×240、检测跳帧、结果 3 帧滑窗滤波；espdet 系列可换 |
| esp_hosted 与 CSI/DSI/SDSPI 总线并发稳定性 | testP4 分项验证过但没同时全开；Phase D 上板做 30min 全负载烤机，掉线自动重连 |
| GAZED 误触发（正脸度阈值） | 阈值进 SD 配置可现场调；HUD 实时显示 frontal_score |
| 16MB 分区重排 = 全擦 | 与 Captain 烧录窗口对齐，一次到位（Phase 0 就切） |
| IO24/25 vs USB 串口（接线阶段） | 本计划不触发；接电机前在 BOARD_MAPPING 里重排 M1 或改用 WS 遥测代替串口日志 |
| LLM/STT/TTS 端点延迟高 | 非流式+短回复；think 表情掩护；超时 8s 落 sad+兜底文案（断网演示本就是卖点） |

## 8. 纪律

- **执行者自主迭代，不逐步请示**：build 失败自己改自己重编到过；自检 FAIL 拿串口日志自己定位、改码、出下一版固件，直到该阶段检查项全绿才向用户汇报。只有「需要真机重刷/回贴日志」「破坏性操作」「方案级改向」才找用户。
- 每阶段 commit 前 `idf.py build` 板外必过（FACE / SELFTEST / TESTPANEL 三模式都编）；flash/monitor/上板验收全部 Captain 手动，不进共享任务。
- AI 产出的上电顺序/LDO/引脚配置人必复核（宪法）；真 key 不进仓库。
- 引脚如有变动同步 CLAUDE.md「固件」节 + `docs/BOARD_MAPPING.md`；本计划落库为 docs/08，协议落库为 docs/09；docs/07 保持为表情子计划真值。
- 复用优先：能照抄 testP4/官方组件的不重写（开发铁律第一级）；自研精力集中在 soul 状态机、motion IK、频道编排。

## 9. 端到端验证（比赛演示映射）

最终一条龙（断网开始）：上电→表情 idle→人走近→APPROACH/ENGAGE 意图数值上屏→盯视 1.5s→GAZED 害羞退后→喊唤醒词（联网后）→问答→语音回答+think 表情→PC 上位机全程看到遥测流。此即 docs/04 演示脚本的"本地视觉感知+自主行为+对话"三段，断 WiFi 后前两段照常 = 比赛杀手锏。
